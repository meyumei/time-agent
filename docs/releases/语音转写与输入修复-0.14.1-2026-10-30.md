# 语音转写与中央输入修复 · 0.14.1

2026-10-30。安装包：`outputs/time-agent-0.14.1-speech-debug.apk`，版本 `0.14.1-preview`，versionCode `25`。

中央按住说话已经修复两个可复现的误取消场景，并改用整段录音的离线 SenseVoice 结果作为最终文字。原仓库的 QQ 收到语音后转文字流程也已接入。当前证据包括 Compose 模拟手势、桌面真实原生模型推理、合成 QQ 接口检查和安装包校验；手机未连接，尚无本轮真机麦克风、实际 QQ 服务或人声准确率结论。

## 中央按钮为什么会误取消

原按钮除了上滑，还把横向移出按钮外一定距离算作取消，界面却只提示“上滑取消”。原代码还比较按钮局部坐标，按钮因布局变化向下移动时，静止的手指也可能被当成上滑。

在旧实现上新增两个实际 Compose 手势用例：

- 按住后仅向侧面移动，再松开。
- 按住时按钮布局向下移动，手指不主动移动，再松开。

旧实现 12 个按钮用例中恰好这两个失败；修正后 12 个全部通过。现在使用窗口坐标计算实际手指位移，仅在向上超过 80dp 后松开才按上滑取消处理。正常松开识别、主动上滑取消、短按提示、读屏操作、权限失败和离开页面时停止录音继续保留。

证据：`evidence/fish-speech-20261030/gesture-red.xml` 和 `gesture-green.xml`。核心代码：`app/src/main/java/com/timeagent/ui/HoldToTalkButton.kt`。

## 识别方式改了什么

原来的小型 Vosk 中文模型继续负责录音时的实时文字预览。录音时同步保留真实 PCM，松开后用内置 sherpa-onnx 2.0.1 / SenseVoice int8 重新识别整段音频，以该结果作为最终文字。松开前已录到、仍在队列中的尾音也会进入最终识别；取消后的迟到结果继续丢弃。

没有用命令词表、语言模型猜测或改写日期、数字来替代实际录音。最终识别没有文字或发生错误时，不把可能错误的预览文字自动当作成功结果。支持最多 60 秒；最终识别在后台线程执行，首次使用需要加载模型。手机上的加载时间、耗时和内存尚待实测。

核心代码：`assistant/OfflineSpeechInput.kt`、`assistant/SenseVoiceSpeech.kt`。模型和来源清单在 APK 的 `assets/asr/sensevoice/`；AAR 在源码的 `app/libs/sherpa-onnx-2.0.1.aar`。

## 原仓库与其他开源实现

先读取原仓库 [luo_sang/qqbot](https://gitee.com/luo_sang/qqbot)，固定提交 `6cbae5ad19cd068e893539753b3f3c54d07543d5`。本地原文：`.tmp/fish-companion-20261029/upstream/bot.py`。

| 原仓库位置 | 解决的事情 | 本项目适配 |
| --- | --- | --- |
| `MediaStore.audio_to_wav`，约 600–638 行 | 从收到的语音文件、base64 或 URL 取得音频，转换 WAV | OneBot/NapCat `get_record` 请求 WAV，必要时下载 WAV 分块 |
| `read_wav_16k`，约 466 行 | 单声道、16 kHz PCM | `core/VoiceAudio.kt` 读取 PCM16 WAV，混音和重采样 |
| `Asr`，约 1013 行 | faster-whisper small/int8，中文识别 | Android 原生 SenseVoice int8，避免装入 Python/FFmpeg/桌面识别栈 |
| 收到语音处，约 3659–3680 行 | 将实际转写文字送入原群会话 | 继续使用原 QQ 群会话、角色和记忆，不创建另一套机器人 |

原仓库没有 Android 的按住说话手势实现，因此无法直接取得手机按钮修复。随后实际读取了以下相关上游实现，并没有声称遍历所有开源站点：

- [RecordView](https://github.com/3llomi/RecordView)：README、`RecordView.java`、`RecordButton.java`；参考录音完成和取消事件分开处理，Compose 修复由本项目实现，没有引入该库。
- [sherpa-onnx v2.0.1](https://github.com/k2-fsa/sherpa-onnx/tree/v2.0.1)：官方 Kotlin `OfflineRecognizer.kt`、`OfflineStream.kt` 和官方 AAR；用于原生离线整段识别。
- [SenseVoice int8 模型](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/tree/2365baeacb507f821a0c8120fcee3d484dba7a07)：固定 revision `2365baeacb507f821a0c8120fcee3d484dba7a07`，模型 SHA-256 `c71f0ce00bec95b07744e116345e33d8cbbe08cef896382cf907bf4b51a2cd51`。

这些上游参考副本在 `.tmp/fish-speech-20261030/upstream/` 和 `downloads/`。Web 检索工具本轮返回空结果；可用资料由官方仓库原文和官方发行物直接取得。

## QQ 收到语音后的行为

“管家”的 QQ 设置增加“语音消息转文字”。启用 QQ 接收后，只处理新收到的语音，最多 60 秒；首次读到的历史和自己的消息不重新转写。转换后的实际文字进入原群上下文，仍按原来的被 @、回复或叫名提问规则决定是否接话。

转写复用中央语音的原生离线模型，不开启麦克风，不调用云端语音识别，不增加语音服务密钥。接收与发送开关继续分别控制，默认均未开启；本轮未发送任何真实 QQ 消息。实际识别文字、处理中或错误会在 QQ 设置内显示。群服务的在线兼容性尚待实际连接验证。

核心代码：`agent-plugins/time-agent/qq-voice.mjs`、`qq-channel.mjs`、`host.mjs`、`fish/FishSession.kt` 和 `fish/FishQQSettings.kt`。
