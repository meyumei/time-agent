# 全局悬浮陪伴

本轮只补充全局显示，沿用现有大肥鱼、档案、换装、动作和会话。入口：管家 → 大肥鱼的一切 → 陪伴与作息 → 全局悬浮陪伴。默认关闭。

## 使用

开启后进入 Android 的“显示在其他应用上层”授权页；授权返回后才开启全局显示，未授权保持关闭。

- 离开主界面后显示在桌面和普通应用上方。
- 拖动调整位置，全局位置单独保存，不移动应用内的鱼。
- 点击回到原管家对话；长按回到陪伴设置。
- 回到主界面时移除全局窗口，使用原有应用内角色。
- 锁屏或熄屏时隐藏；解锁后重新显示。
- 关闭设置开关或通知中的“关闭全局显示”即可移除窗口，不停止原管家运行。

这次没有新增全局聊天框、屏幕读取、无障碍服务或开机自启；全局窗口只负责角色显示及回到原页面。系统和其他应用仍可限制悬浮窗显示。未承诺绕过手机省电或后台限制。

## 实现

`FishOverlayService` 是独立的用户启动前台服务，持有角色大小的 `TYPE_APPLICATION_OVERLAY` 透明窗口，直接复用 `FishSession.current()` 和 `CharacterSprite`。它不创建第二份人格、记忆或模型运行时；停止该服务不调用原运行时的停止逻辑。

窗口不获取键盘焦点，外部区域可操作原应用。拖动使用屏幕坐标，触摸取消不触发聊天。屏幕、安全区域和横竖屏变更用于限制窗口位置。Android 11/API30 起使用关联显示器的窗口上下文，旧版使用实际屏幕尺寸与窗口系统边距。

点击使用原 MainActivity 的重新前置行为，不清除叠在其上的训练或记账页面。导航参数读取后即移除，防止旋转重放。

## DS 协作与问题处理

真实 WorkBuddy/CodeBuddy CLI 的 `deepseek-v4.1-flash` 执行评审、编写四项原生手势与设置检查，并通过固定验证入口执行本地检查。请求 effort `max`，实际模型由日志核对；服务端实际档位未得到证明。

独立核查并处理了 DS 的四项发现：

1. 旋转时旧导航参数重新打开管家或设置：读取后移除参数。
2. 拖动尚未抬手就锁屏时位置丢失：移除窗口前保存当前位置。
3. 旧 Android 的应用可用区与屏幕坐标不一致：使用实际屏幕坐标并扣除收到的系统边距。
4. `CLEAR_TOP` 会结束未退出的训练、记账页面：改为把原 MainActivity 重新前置，保留其他页面。

这些修正的真机交互仍需验证，不能把源码分析视为硬件通过结果。评审原文保留在 `evidence/fish-global-20261031/`。
