# 个人管家 0.11.0 使用与验收

本轮在 0.10.0 基础上加入项目与周目标、周期习惯、生活期限、回复副驾、附件收件箱与系统日历交接。桌面小组件、物品、旅行、设备联动、多用户及云同步不在范围内。旧任务不会被猜测归属，训练模块完整保留。

按用户最后要求，收敛实现和新增模拟测试，先交付完整安装包供手机测试。构建与必要数据检查通过后交付；桌面检查不代表手机上的通知、文件选择器、OCR、日历或触控已经验证。

## 项目与周目标

“任务 → 项目与子任务”创建项目、明确加入已有任务或创建一级子任务。项目有截止日期和状态，子任务不会自动代表项目整体完成。移动有子任务的父任务时，先处理子任务归属。

“复盘 → 周目标”设置项目或活动的本周投入目标。完成数量、计划投入、累计实际和去重时间分别显示；点击统计查看原任务、计划或实际记录。实际按所选周与当前时刻裁剪，开放计时不当成整天实际。今日简报显示临近截止和逾期项目。

## 周期任务与生活期限

“任务 → 周期任务与习惯”支持每日、指定星期和每周次数。周频次只有目标实例，不强行排固定时段。完成、跳过、改期、暂停与重开都保留原始实例来源；修改可区分仅本次与本次及以后。漏做不补打卡，不生成实际记录，手动修改和历史实例不被规则刷新覆盖。

“任务 → 生活期限”录入续费、归还、报销、生日或其他期限。支持一次、每月、每年、资料说明、提前提醒、处理和延期。每月31日在短月取月末，后续月份回到原锚点；2月29日在非闰年取2月28日，闰年回到29日。明确录入的逾期或远期期限仍留为待处理事项。

提醒依赖系统权限及省电策略。过去未触发的提醒不补发；已提交给系统不代表用户一定看见。手动关闭或删除提醒后，改规则、延期和重启不会擅自恢复。自动暂停与手动停用分别处理。

## 回复副驾

从“任务 → 回复副驾”进入，或在聊天文字提取页面选择“结合空档起草回复”。粘贴或分享文字，选候选、日期、查询范围和另约时长，再核对空档。只使用本应用的计划、课程、实际记录及个人约定，外部日历没有同步。

接受只针对原文明确且空闲的起止时段；另约使用当前核对的空档；时间不明确时可先生成确认问题。正在计时而尚未结束时，后续时段保守视为占用，结束计时后重新核对。

生成草稿不会写入日程。回复文字可自由修改；“复制回复”只放入剪贴板，实际发送未确认。单独勾选“这是我的安排”后才能保存下方结构化安排，保存时再次检查冲突和个人约定。修改回复文字不会修改结构化安排，撤销安排也不会撤回已复制文字。没有自动发消息功能。

## 附件与日历

“任务 → 附件收件箱”主动选择文件，原件复制到应用私有目录，不依赖选择器URI长期有效。可明确关联一个项目或任务，图片可识别成可纠正的文字草稿；文字保存由用户确认，不自动变成任务或承诺。其他文件保留原件，不能识别时仍可手工填写文字。

删除先进入回收站，原件保留以支持撤销。清除本机原件不可撤销，条目和文字保留并显示文件缺失；恢复条目不能凭空恢复已清除文件。备份携带存在的原件与关联数据，缺失文件明确计数，恢复不会把过期URI或缺失文件说成完整恢复。

在时间轴选择计划或课程，点击“交给系统日历确认添加”。标题、时间和可选说明由用户核对，说明默认空白。打开系统添加入口后，仍须在日历中自行确认；本应用无法核实系统是否真正保存。不申请日历读写权限，不进行双向同步。

## 验证与手机测试

阶段1、2、3的定向验收分别记录在 `outputs/butler-next-stage1-verification.json`、`butler-next-stage2-verification.json`、`butler-next-stage3-verification.json`。最终安装包的版本、签名、资产和构建一致性记录在本版机器报告中；最终统计以报告为准。

手机优先试：原有数据是否保留、项目及周期操作、期限通知与权限、分享文字与复制回复、文件选择与中文图片识别、带附件备份及日历添加入口。不要用真实重要数据做替换恢复演练，先导出副本。
