# T1.2 ClockSource 与秒级重组修复

日期：2026-11-01。分支 `codex/t1.2-clock-source`，基于 T1.1 提交 `072ae14`，PR 以 `codex/t1.1-hilt-databases` 为基底。按用户要求转入方案开发，未继续 T0 真机补证。

## 实现

`core/ClockSource.kt` 提供可注入的墙上时间、`minuteTicks`、`secondTicks` 和 `elapsedRealtime()`。两个 Flow 都是冷流：收集时立即发出当前时间，然后对齐下一秒或下一分钟；取消收集即停止，构造实例本身不读时钟、不启动任务。每次唤醒读取实际墙上时间，手动改时间后在下次唤醒反映变化并重新对齐。Android Hilt 单例把单调时间接到 `SystemClock.elapsedRealtime()`，未用 JVM 时钟替代 Android 的开机经过时间。

`TimeAgentContent` 不再订阅 `now`。计时条提取到 `RunningTimerBar`，只在该条显示且界面生命周期活跃时收集 `secondTicks`。时间轴、简报、复盘、项目、周目标、编辑器和详情通过 `MinuteClockContent` 读取分钟时间；截止、周期和个人规则页也按生命周期收集分钟时间。原有页面布局、文案、回调、导航和写入行为保留。

`TimeViewModel.now` 保留为兼容未迁移页面的分钟 `StateFlow`；周状态保留跨日更新，周期刷新仍以 UTC 小时变化为触发条件，初次初始化刷新也保留。ViewModel 为这项已有维护工作主动收集分钟时间，明确采用 Eagerly；“仅在收集时运行”指 ClockSource 不自建常驻作用域，不代表取消既有周期维护。页面恢复前台时向该状态补发 `clock.now()`，避免长时间休眠后重放旧分钟、等待尚未走完的 uptime 延迟。

主库仍 v12、训练库仍 v1。没有数据迁移、业务规则修改或功能删减；没有改大肥鱼、Linux/DSH、BYOK 或训练计时实现。手机未安装开发 APK，也未执行数据恢复。

## 验证方法与失败证据

使用现有 Robolectric + Compose 测试环境和编译器的 `CompositionTracer`，直接统计真正的 `TimelineScreen` 与 `TimeAgentContent` 调用；未向产品源码加入重组计数器。测试先确认跟踪器确实观察到这两个组件，再统计后续 5 秒，同时断言计时文字从 0 秒走到 5 秒，避免“计时也停了所以没有重组”的假通过。

在旧实现运行同一个 5 秒断言，真实得到 `timeline=5 root=5`，因应为 0 而失败。局部订阅实现后的专项结果为 `timeline=0 root=0`；分钟边界更新和跨午夜维护也通过。ClockSource 首次契约检查失败于 API 尚不存在，这是新增 API 的编译失败记录，不能冒充对旧实现的功能失败；实际性能缺陷由前述 Compose 失败回归证明。

独立规格审查另指出，注入假时钟时周导航仍取仓库时钟日期。本轮补上不同日期来源的测试，要求初始周与“本周”均采用注入的 ClockSource；业务仓库的写入时间来源仍保持原有实现。

代码质量审查指出休眠后的分钟缓存可能过期。回归只暂停页面生命周期并把墙上时间推进一天，不推进 Looper 或分钟延迟；改动前预期 `2026-10-20T08:00:10Z`，实际仍为 `2026-10-19T08:00:10Z`。据此加入 ON_RESUME 刷新。另用计数时钟直接检查秒流的收集生命周期；计时条原本在多个 Tab 顶部可见，因此切 Tab 保持一个订阅，不能采用“切到计划或复盘就必须为零”的建议。

新增订阅测试最初还有两项夹具问题：点击打开编辑器后未等待 Compose 完成更新，导致立即读取到旧订阅数；测试时钟被冻结在计时开始瞬间，停止被现有“请至少计时一秒后结束”校验拒绝而超时。已分别等待界面稳定、在停止前推进一秒，没有修改停止计时的业务校验。失败输出保留于 `resume-initial.txt`、`resume-red.txt`，不得将这两项夹具失败冒充产品缺陷。

完整回归命令与统计见下方本轮结果；原始输出留在本机 `evidence/t1.2-clock/`，提交的文本证据只归一化换行、展开制表缩进，不删除警告、失败或跳过记录。
