# T5.3 通知栏开始最近计时

2026-11-05。仅开发、源码核对与 Kotlin 编译记录，未作功能验收通过声明。

## 改动

无计时快捷通知的“开始最近计时”从打开管理页改为直接执行快捷记录。通知生成时冻结快捷项 ID、内容版本和使用次数，以此生成稳定请求编号。非导出的广播接收器经 CommandExecutor 执行 WriteQuickEntry.Perform，保留幂等、版本检查、事务与原有历史撤销。

最近项从完整快捷记录中筛选自由计时或专注，按最近使用时刻、使用次数、显示顺序和 ID 确定。桌面今日概览复用同一选择函数，创建日程/实际的预设不参与。没有可用计时预设时打开管理页配置。

启动请求不携带已确认运行槽位；如果通知显示后另一个计时、专注或训练已开始，命令拒绝，不自动结束它。失败通知显示返回原因，点击打开普通快捷管理页，用户重新选择。没有连接会在打开时尝试执行的 `quick-entry-confirm` 路由，避免失败提示成为自动重试。

通知状态流新增观察 quick_entries，并把最近项纳入去重状态。快捷项修改、删除或使用后会更新通知，不再仅靠计时表变化刷新。原停止/暂停、语音、新建任务、隐私设置和前台服务保持。

## 暂停的验收与限制

按用户要求未执行单元、Node、迁移、仪器、性能、lint 分析或手机操作。

恢复验收后需要：

- 开启快捷通知，无运行项时连续点按开始最近自由计时/专注，确认只创建一次；停止后可再开始。
- 通知显示后修改/删除预设、另开自由计时/专注/训练，确认旧通知拒绝覆盖，失败消息可见且打开管理页不执行。
- 无预设、只有创建日程/实际预设、最近项不在前四个芯片中，确认选择与空态。
- 锁屏、进程被杀、通知权限关闭、前台服务限制下核对开始、错误反馈和计时数据；本地业务不依赖鱼、Key 或网络。
- 检查原停止、暂停、语音、新任务和撤销历史；大字与 TalkBack 检查按钮可达。

N02 的 ActionCallback 失败自动打开应用仍未解决；现有小组件失败提示需再次点按。`quick-entry-confirm` 的打开即执行行为单独列为后续修正。阶段 2–5 仍未全项完成。
