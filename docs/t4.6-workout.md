# T4.6 训练导航与主计时

日期：2026-11-04。分支：`codex/t4.6-workout`，开发基线：`c061c6b`。

## 本轮改动

训练页面接入主导航并使用主应用主题。旧 WorkoutActivity 保留为通知与深链跳转入口；训练首页、会话、动作库、GIF、3D 肌肉、模板编辑、超级组、Tabata、休息和单组计时原页面继续使用。今天顶部显示进行中或暂停的训练，点击返回该会话。

训练开始、模板开始、复训和动作库开始经过同一个 ViewModel 入口。存在自由计时时，先显示切换确认；确认提交保留原计时 ID 和版本，取消不写库。反向从训练切换到自由计时时，保存已完成组的训练，或放弃没有完成组的空训练；目标任务和训练均检查所见版本。冷启动的 Repository 也绑定训练库，鱼和通知入口不能另开一个主计时。暂停训练继续占用槽位。

训练与模板写入接入 CommandExecutor。请求结果落主库，训练实体以单调 updatedAt 检查版本，操作快照参与统一撤销、重做。模板删除、结束或放弃训练传入界面所见版本；模板草稿不会自动改成最新版本重提。

结束训练只生成固定 ID `workout:<sessionId>` 的一条实际记录，来源为 WORKOUT。重复结束不会重复生成；用户删除该实际记录后也不会重新创建。已完成但缺少关联的会话可重新结束补关联，使用新补链请求避免旧结果重放挡住恢复。训练行、关联标记与主库提交由本次行恢复文件协调；撤销也兼容旧版本主库已提交而关联尚未落库的会话。

## 集中真机验收步骤

1. 从管家、今天训练条、训练通知分别进入训练；返回和切换 Tab 后会话、动作选择、模板草稿保留。
2. WEIGHT_REPS、REPS、DURATION、BODYWEIGHT_REPS、ASSISTED_REPS、CARDIO、STRETCH、TABATA 各录一组；普通、热身、递减、力竭各一次。核对 GIF、3D 肌肉、超级组、Tabata、休息与单组计时和模板编辑。
3. 自由计时存在时，从自由训练、模板、复训和动作库四入口开始；取消不写入，确认后结束原计时并开始训练。确认前更改原计时版本，再提交旧确认，应冲突且不部分保存。
4. ACTIVE、PAUSED 训练期间从本地、鱼工具和通知尝试开始计时，均不得绕过互斥；界面明确确认反向切换，空训练不产生实际记录，有完成组的训练保存一条实际记录。
5. 完成训练、重复完成、响应丢失后重试；核对仅一条 WORKOUT 实际。删除实际记录后再次结束不能复活；撤销、重做结束操作应联动会话与实际记录。
6. 打开旧模板后从另一入口编辑，再保存或删除旧版本，应报告冲突；撤销模板删除后可再次删除。
7. ACTIVE 和 PAUSED 后分别杀进程、后台、锁屏再启动，核对状态、暂停总时长、休息提醒和主计时恢复。
8. 已在隔离包注入未提交开始切换、未提交完成、已提交标记和首次文件写入中断状态，实际终止并重启进程检查恢复；6 项通过。尚未在执行中的两个数据库提交之间精确计时杀进程，不能将注入状态验证描述为该时序验证。

## 已知限制与回滚

workouts.db 和主库是两个独立 SQLite 数据库。本轮新增仅用于训练命令的行恢复文件：每个训练/模板行首次写入前，用 AtomicFile 保存其原值；同一主库事务写入提交标记。普通异常逆序恢复训练行；被杀进程后，在下一次训练读取、用户命令或备份采集前检查标记，未提交则恢复原行，已提交则保留结果并清理恢复文件。恢复前先移除本次涉及的训练行，再放回原值，避免唯一 activeSlot 与本次新训练冲突。恢复文件留在应用私有数据库目录，不进入仓库、不发送给 DS。已完成上述中断状态注入、真实进程重启与单条实际记录检查；精确命中两个提交之间的实际进程终止时序仍未验收。

代码可单独回退，无降级迁移。回退代码不能自动撤销用户已完成的训练和主库实际记录；应先核对数据并使用操作历史或已验证备份路径。训练库与主库的完整备份 v2 仍属于 T6.2，尚未因此完成。
