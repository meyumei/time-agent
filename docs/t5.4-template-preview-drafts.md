# T5.4 模板应用预览与编辑草稿

日期：2026-11-05。影响 L01/L03/L05/L07；关联 N09、T2.4/T2.5。

## 实际改动

- 模板任务条目有 startTime 时，既有执行逻辑会创建任务及关联日程。预览原来只显示“任务”，现明确显示关联日程时间/提醒点/全天类型，确认按钮分别统计将创建的任务和日程数量。
- 一个任务条目和其关联日程仍是同一个选择单元；取消会一起取消，预览明确说明此行为。未修改模板的写入数量或事务语义，没有擅自引入“保留任务但单独取消其日程”的新产品行为。
- 模板编辑的名称、说明、条目、正在编辑的条目和未通过校验的文本草稿每两秒防抖写入本地偏好。草稿不是正式业务写入，不创建日程/任务。
- 顶栏关闭和系统返回接入保留草稿/丢弃/继续编辑。条目弹窗也有独立退出确认；保留会保存当前弹窗内容及父模板编辑后退出。
- 模板列表提供恢复入口，包括尚未正式创建的新模板。恢复时使用草稿原先看到的模板及原始条目，不将当前数据库版本替换为“已确认版本”；正式保存仍走现有 SaveTemplate 事务、版本和历史机制。
- 正式保存对当前字段组合使用稳定 requestId，失败重试不重新生成同一请求；字段变化会生成新请求。成功后清除草稿，清除失败明确告知并禁用重复保存。
- 模板父级保存正在编辑的原实体，并按模板 ID 隔离保存状态；关闭时清理该状态，避免重建后选择另一模板串入前一个模板字段。
- 子弹窗明确丢弃时立即同步更新父草稿或移除无修改的草稿，不等待两秒防抖，避免切走页面后已丢弃内容恢复。
- 共享 rememberDraftExit 新增可选 initialFields；字段改用结构化 JSON 比较，避免名称/说明中的逗号使 List.toString 相同而漏掉修改确认。模板从原始字段判定修改，避免恢复后的脏草稿被误认为初始未修改状态。其他调用者为任务/日程/实际和笔记编辑器，因此这些退出确认也列入待回归范围。

主库仍 v22，训练库 v1，没有 schema 变更。没有改训练模板、快捷记录业务或鱼/运行时。新增草稿偏好暂未加入备份 v2，属于后续 T6.2 的完整偏好覆盖，不宣称格式 v1 已覆盖。

## 尚未执行的验收

1. 模板同时含独立任务、带关联日程的任务、普通时段/提醒点/全天日程；预览时间、选择单元与确认数量必须和正式创建一致，一次撤销恢复整批。
2. 修改名称、说明及条目后，分别通过顶栏、系统返回和弹窗外点按，核对保留/丢弃/继续；未通过校验的日期跨度/提醒文本也应恢复。
3. 新建未命名模板及编辑已有模板，等待两秒后退出/旋转/杀进程，模板列表恢复相应草稿和正在编辑的条目；无草稿不显示伪恢复入口。
4. 从其他入口修改或删除模板后恢复旧草稿，正式保存必须拒绝旧版本而不覆盖；失败内容保留，重复请求不得重复保存。
5. 模板已保存但草稿清除失败、偏好写入失败、200%字体、TalkBack、无网络/Key/运行时，以及备份恢复后旧草稿的版本拒绝仍需核对。
6. 在模板A编辑时重建后返回再打开B，核对没有混用字段/保存对象；子弹窗丢弃后立即切Tab再冷启动；名称/说明含逗号的字段迁移仍应询问退出。任务/日程/实际和笔记的共享退出确认需回归。
