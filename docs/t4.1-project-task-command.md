# T4.1 项目内新增任务的统一命令

2026-11-05。仅源码与必要编译，测试和手机操作保持暂停。

## 问题与改动

项目页“新建任务/子任务”原来在旧 assistantTransaction 中分别调用 saveTask 和 savePlacement。两个公共方法各自进入 CommandExecutor，外层请求编号在每次点击时生成，也没有显式核对项目及父归属的所见版本。源码复核确认：原方案已有外层事务回滚，commandWrite 会继承外层历史收集器，因此旧方案并非一定拆成两次撤销；本批不把整组撤销冒称为首次实现。

本批新增 ProjectMutation.CreateTask，由一次 WriteProject 执行任务和归属的 raw 写入。先核对项目内容版本、新任务及新归属不存在；选择父任务时核对父归属所见版本。既有归属校验继续保证父任务存在、只支持一级、父子在同一项目。任何一步失败由外层事务回滚，任务和归属进入同一命令历史。

新任务编号在弹窗中稳定；提交请求编号按表单字段保存，同一内容重复点按复用 requestId。保存中阻止重复确认和关闭，成功后清空表单并显示共享八秒撤销。撤销顺序先处理归属再处理任务；不创建实际记录。

影响 L01/L03/L05。没有 schema、迁移、周期身份、鱼运行时或共同记忆变更。

## 核对与编译

源码核对旧调用链、CommandExecutor 的 commandWrite/事务、版本检查、两次 raw journal 顺序、弹窗请求和任务编号，以及结果 undoToken 到共享反馈的连接。

实际命令：

```powershell
./scripts/build.ps1 -Tasks @(':app:compileDebugKotlin')
```

## 暂停的验收与剩余范围

- 项目新建普通任务和一级子任务，核对项目归属、预计时长与任务数量；不产生实际记录。
- 连续点保存、旋转/重建时保存、同请求重放，只产生一项。
- 父任务归属改变、项目更新/删除后保存，冲突时任务和归属都不残留。
- 一次撤销同时撤回新任务及归属，重做恢复整组；确认八秒提示和历史恢复。
- 保存期间返回、失败后输入保留、200%字体与TalkBack。

以上均未执行。项目/周目标/项目任务等表单的磁盘草稿仍需要独立补齐，本批固定编号与 rememberSaveable 不冒充持久落盘。旧 assistantTransaction 的其他调用点也不因本批而自动视为迁移完成。
