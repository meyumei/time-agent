# T5.8 系统日历双向同步

2026-11-04。开发记录，未作验收通过声明。

v19→20新增calendar_links和calendar_sync_state。设置可选多个日历与方向、导出目标、独立实际记录日历；默认过去30/未来365天，两端范围均可修改。原发送到系统日历Intent保留。

应用打开、日程变化10秒防抖、系统日历ContentObserver、每6小时触发同步。保存九字段hash防回声，保留原时区和UTC全天日期；来源标记用于失败后的映射核对。权限丢失暂停并保留本地数据和映射，provider读取失败不会被当成远端删除。

远端删除同步为本地软删除；用户恢复后，双向日历可重新写远端，仅导入时保留为独立本地日程。本地删除外部来源需确认。两端冲突保留双方快照和一键选版，检查页面所见映射版本及当前本地版本；选本地会恢复本地快照，选远端在需要时更新已写回的系统版本。

周期保留RRULE原文及本地周期存储，单次例外通过系统exception接口操作，不覆盖整个系列。不支持的规则/日期语义只读并解释。断开时可保留导入为本地/软删除，导出可留/删；同时解除映射与周期来源。设置、断开、版本选择保留命令历史。

系统provider与Room无法组成同一事务，外部写入失败会如实报错并在下次按标记核对；系统日历云同步时效不作保证。多数provider没有真实修改时刻，自动冲突判断只能参考本地时刻与最近同步点，双方快照与手选入口保留；不能声称准确比较远端最后修改时间。

影响L01/L06/L07/L36。恢复验收时新增/编辑/删除、回声、周期单次例外、冲突双方恢复、范围、权限撤销、断开/撤销及1000事件性能；本轮均未执行。
