# T5.7 提醒点导出与长阶段进度通知

2026-11-05。仅实现、源码检查和 Kotlin 编译，未执行导出或设备验收。

## 改动与依据

源码对照发现 CSV、JSON、ICS 的日程筛选只接收正时长或全天日程。提醒点按现有约束起止相等，所以被漏掉。本批在三处查询显式加入 POINT 分支，时间范围采用开始包含、结束不包含；保留原正时长/全天分支、删除过滤、ICS 的 SCHEDULED 过滤及示例排除。

ICS 的提醒点只写 DTSTART，省略 DTEND。已读取 RFC 5545 §3.6.1 和 §3.8.2.2 原文：DATE-TIME 事件不写 DTEND 时在开始时刻结束；若写 DTEND 则必须晚于 DTSTART。其他日程的结束字段保持。

原超过两秒的进度通知只在写入阶段边界判断，单个 JSON/CSV 类写入很久时没有显示机会。现在由导出工作作用域内的协程两秒后显示最近阶段，每秒低频更新；退出作用域时取消并等待该协程，然后才进行完成/失败通知及清理，避免迟到进度覆盖完成状态。没有为每条数据写进度，也没有新增独立后台作业。

## 影响与核对

L01/L07，关联 N05。无数据库迁移或容量上限调整。原临时文件、取消清理、用户所选位置和流式输出路径保留。

主代理逐一核对三处 SQL 占位符与参数顺序、POINT 边界、ICS 字段分支，以及通知协程的取消与完成顺序。该问题由独立只读源码对照发现，未在设备复现。

## 暂停的验收与限制

未运行测试、lint 分析、导出执行或手机操作。恢复后需要：

- 同一区间准备时段、全天、提醒点、已删与示例日程，分别导出 CSV/JSON/ICS，核对数量、边界及排除。
- 开始边界的提醒点应包含，结束边界不包含；全天跨日和跨时区保留原语义。
- 使用外部日历打开 ICS，核对提醒点零时长表现及其他日程结束时间。
- 单个数据类或目标位置写入超过两秒时，核对进度出现；完成、取消和失败后进度不复活，通知取消仍清理文件。
