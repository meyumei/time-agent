# 第七轮需求与实施记录

日期：2026-10-21。基线：0.4.1。

用户新增七项要求：

1. 排查并改善双指放大缩小的卡顿，保留连续日期与完整全天视图。
2. 新计划默认建立任务点提醒，到点发手机系统通知；只有用户明确指定起止时段或主动选择时段时才占用日历时间，不能默默补出一小时。
3. 点击课程、任务、计划、实际记录或活动模块后提供“记笔记”入口，笔记与对应模块关联，可再次查看、编辑。
4. 新增“未安排”想法收集：文字或语音收集灵感，不要求日期，不自动占用时间；可之后再安排。
5. 在撤销之外提供重做（恢复刚撤销的操作），新编辑使旧重做分支失效，数据版本不能回退。
6. 增强口语、单时间点、灵感表达及上下文理解；保留日期推断、明确时段记录、否定不写入、修改删除与安全撤销。区分识别文字质量与意图解析，不把本地模拟测试称为真机识别率。
7. 冲突课程先提供独立原生视觉示例，用户满意后才替换正式排版。用户已在本轮确认采用“A+B：周视图用A，展开后用B宽卡”，正式接入已获授权。

用户指定分工：Antigravity Gemini 3.8 Flash 负责原生冲突视觉样例与缩放分析；WorkBuddy DS v4.1 Flash 负责语义建议与测试；主控负责数据、系统提醒、笔记、未安排想法、重做及集成验收。实际调用和不可用原因必须留证据，不以本地助手冒充指定模型。

接口与数据目标：Room v3 增加 reminder、idea、note 表，并显式迁移 v2；历史追加重做状态。提醒点与日历区间分开存储，想法不带计划时段。通知按 Android 系统权限和闹钟能力调度，重启恢复；撤销、删除、改时取消旧通知。笔记只在用户选择进入后编辑。

交付保持本地 APK 和 Markdown；不连接手机，不传输，不生成 HTML 展示。冲突示例以原生界面截图提供，已通过点击展开测试；批准后的正式接入将合并周视图中的重叠组，再展开完整宽卡。

模型调用进度：Gemini `gemini-3.8-flash-high` 已实际生成原生样例与性能分析。原 WorkBuddy 随应用 CLI 因登录入口不同返回鉴权错误；用户安装并登录官方 CodeBuddy CLI 后，已确认 `deepseek-v4.1-flash` 调用成功。按用户追加要求，后续功能实现尽量交由 DS 工具执行，主控负责拆分、集成检查、测试与打包。证据见 `evidence/iteration7-workbuddy-ds41-flash-ready.txt` 及各任务流日志。

开发前期已分域补充定位用例并串行运行。用户最新要求“你不用跑回归，他们修改完直接给我apk”，覆盖原先的最终回归计划：模型完成源码后仅编译打包、校验 APK 签名和版本，直接交付本地安装包。最终源码不运行回归、Lint或新增测试轮，不以早期测试结果宣称最终版本已全部通过。具体产物在交付记录填写。
