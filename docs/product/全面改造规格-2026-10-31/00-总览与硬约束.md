# 时间 Agent｜产品级全面改造规格与 Codex 执行计划

> 🧭 本文档是时间 Agent（`meyumei/time-agent`）从 `0.15.2-preview`（versionCode 28，基线提交 `660d129`）走向“成熟产品完成度”的全面改造规格。读者是 Codex 与维护者：每一章都可以单独交给 Codex 执行，但必须遵守本页的硬约束与第 8 章的任务顺序。

## 一句话目标

在**不删除任何现有能力**的前提下，把时间管理＋个人管家＋大肥鱼陪伴整合成一个导航清晰、操作一致、数据可靠、离线可用、可长期使用的 Android 应用；保留 Linux＋DSH 运行时，但让原生业务不依赖它。

## 已确认的决策（最高优先级，任何章节与之冲突时以此为准）

## 给 Codex 的总规则

1. **先建账本再改代码**：任务 T0 产出功能保留账本与基线测试；任何 PR 都要在账本中勾选受影响项并附证据。
2. **区分“现存”与“拟建”**：文档中路径或字段带「拟建」标记的尚不存在；未标注的文件路径是 `660d129` 中真实存在的文件（`ui/…`、`data/…` 等相对于 `app/src/main/java/com/timeagent/`）。禁止假设拟建字段已存在。
3. **小步可回滚**：每个任务独立分支，数据库迁移必须有迁移测试和失败回滚说明；不允许一次性重写整个 `TimeAgentApp.kt` 后再补功能。
4. **不以单测全绿为完成**：涉及 UI、权限、后台、锁屏、进程被杀、迁移的任务必须附真机或模拟器验收记录。
5. **不做硬承诺**：Android 厂商杀后台、系统日历云端同步时效、第三方平台接口稳定性不能保证，只能做恢复、诊断与提示。
6. **遇到本文未定义的产品决策**：停下来列出选项提问，不要自行删功能或改变已确认决策。

## 现状速览（基线 660d129）

- 单 Activity + Compose，`ui/TimeAgentApp.kt` 约 733 行，字符串导航栈与几十个状态；无 Navigation Compose / DI。
- `TimeViewModel` 每秒更新 `now`，根 UI 订阅，导致大范围重组。
- 主库 Room v12（29 表）、训练库 `workouts.db`、共同记忆在 DSH 侧 Python/SQLite；`TimeRepository.observe()` 监听 25 张表并重建全量快照。
- `ScheduleBlockEntity.taskId` 必填（外键 RESTRICT），独立日程无法存在。
- 鱼正常运行时 `TimeViewModel.fish` 非空，所有输入都发给鱼，绕过本地解析；运行时未就绪时直接提示“先启动内置角色”。
- 时间轴 `FIT_DAYS=7`，一个缩放同时控制两轴，工具栏拥挤，触控 28–34dp。
- 日期时间大多为手输字符串；无 `strings.xml`；子 Activity 主题不一致。
- 环境说明：本次规格编写未构建、未真机测试；README 中历史测试数量不能作为本轮质量证据。
