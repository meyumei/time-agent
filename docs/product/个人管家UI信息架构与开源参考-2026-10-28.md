# 个人管家 UI 信息架构与开源参考

> 本文保留 UI 研究依据。结合多平台大肥鱼与 QQ 复用后的功能归属、页面骨架和启动顺序见[统一启动方案](../research/时间Agent与大肥鱼-统一启动方案-2026-10-28.md)。

日期：2026-10-28  
范围：功能归类、导航重构、子页面模板、开源项目与研究工具

## 结论

当前主要问题不是功能太多，而是功能按开发模块堆叠，用户却需要按“我要完成什么”来进入。

建议保留少量一级入口，但把入口从功能名称改成用户任务：

1. **今天执行**：时间轴、今日待办、逾期、快速记录、计时。
2. **计划组织**：项目与子任务、周期任务、生活期限、收件箱。
3. **复盘洞察**：周目标、项目复盘、健康与训练、历史记录。
4. **管家与设置**：助手、个人记忆、备份恢复、系统交接、权限和外观。

项目、习惯、期限、训练、健康、助手和附件都可以从相关任务流进入，但不应继续各自争夺底栏入口。

## 当前实现观察

当前代码已经有“时间轴 / 任务 / 复盘 / 我的”四个顶层标签。任务页继续分出收件箱、项目、周期任务、生活期限、附件、回复副驾和训练等入口，设置页也承载导入、活动、助手、健康、训练、备份、记忆、历史和文字提取。

证据：

- 顶层标签与任务页入口：`app/src/main/java/com/timeagent/ui/TimeAgentApp.kt`
- 项目页预览：`outputs/butler-next-previews/projects.png`
- 周期任务预览：`outputs/butler-next-previews/recurring-weekly.png`
- 生活期限预览：`outputs/butler-next-previews/deadlines.png`
- 周目标预览：`outputs/butler-next-previews/project-review.png`

这些预览共同表现出几个问题：

- 页面大量依赖文字按钮，主操作和次要操作权重接近。
- 卡片承担了太多内容，状态、统计、规则和操作没有清晰分层。
- 页面间缺少统一的列表、详情、编辑和反馈模板。
- 视觉留白较多，但信息密度和可扫描性仍然不足。
- 功能入口存在，但用户很难判断“该从哪里开始”和“完成后回到哪里”。

## 建议的信息架构

```text
今天执行
├── 时间轴：日/周视图、课程、计划、实际记录、冲突
├── 待办：今日任务、逾期、临近截止
└── 快速记录：语音、文字、自由计时、补录

计划组织
├── 项目与子任务：目标、阶段、任务归属
├── 习惯与周期：规则、今日实例、历史
├── 生活期限：待处理、延期、已处理
└── 收件箱：想法、附件、分享文字

复盘洞察
├── 周目标：投入目标、完成量、实际耗时
├── 项目复盘：计划、实际、剩余任务、截止日期
├── 健康与训练：睡眠、运动、健康来源状态
└── 历史与记录：回到原任务、计划或实际记录

管家与设置
├── 助手：对话、建议、回复副驾、个人记忆
├── 数据：备份、恢复、导入、导出
├── 外部交接：系统日历、通知、权限
└── 外观与实验：主题、诊断、实验入口
```

这是一版可测试的假设，不应直接当成最终答案。最终分类需要用真实任务做卡片分类和树测试。

## 功能到页面的归属

| 现有能力 | 用户真正想做的事 | 主入口 | 页面内组织 | 高频主操作 |
|---|---|---|---|---|
| 时间轴、课程、计划、实际记录 | 今天安排和执行 | 今天执行 | 日/周、类型筛选、冲突 | 新建、开始计时、完成 |
| 项目、子任务、周目标 | 推进持续目标 | 计划组织 | 项目列表、项目详情、阶段 | 新建项目、拆任务、安排 |
| 周期任务、习惯 | 按规则重复完成 | 计划组织 | 规则、今日实例、历史 | 本次完成、跳过、修改以后 |
| 生活期限、提醒 | 不要忘记重要日期 | 今天执行 + 计划组织 | 今天、7 天内、以后、已处理 | 处理、延期 |
| 想法、附件、分享文字 | 先收集，之后归类 | 计划组织 | 未处理、已关联、待确认 | 归项目、转任务、忽略 |
| 训练、睡眠、健康同步 | 记录身体状态并看趋势 | 今天执行 + 复盘洞察 | 训练、睡眠、来源状态 | 开始训练、同步、查看趋势 |
| 助手、回复副驾、个人记忆 | 更快理解和决定 | 管家与设置 | 对话、建议、记忆 | 询问、起草、确认写入 |
| 备份、导入、日历交接、权限 | 管理数据和外部系统 | 管家与设置 | 数据、外部交接、权限 | 导出、确认交接、授权 |

## 每类页面的统一模板

先统一交互骨架，再做视觉风格。建议固定五段：

1. 页面标题与范围。
2. 状态摘要。
3. 主列表或主内容。
4. 一个明确的主操作。
5. 更多设置、危险操作和低频操作。

每页都需要定义：加载、空、错误、已完成、处理中和无权限状态。

### 项目页

顶部显示项目状态、截止日期、当前阶段和下一项任务。编辑、删除、周目标、加入已有任务放进项目详情或溢出菜单。项目列表只承担浏览和进入详情。

### 周期任务页

默认先看“今天要做的实例”，再看规则。必须把“规则编辑”和“只改本次”做成两个不同入口。

### 生活期限页

按“今天、7 天内、以后、已处理”分组。每条只露出“处理”和“延期”两个高频动作，通知设置放到详情。

### 复盘页

统计数字必须可以回到原任务、计划或实际记录。图表用于看趋势，明细用于解释数字。

### 设置页

按“助手、数据、外部交接、外观”分组。业务入口不要继续和系统设置混在一个长页面里。

## 参考资料与开源项目

### 导航与信息架构

- [Android：Layouts and navigation patterns](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)：底部导航适合 3–5 个同层级目的地；tabs 和底部应用栏可作为子页面或辅助导航。
- [Android：Build adaptive navigation](https://developer.android.com/develop/adaptive-apps/guides/build-adaptive-navigation)：为手机、平板和更大窗口保留同一信息架构，再根据窗口改变导航呈现。
- [NN/G：Information Architecture Study Guide](https://www.nngroup.com/articles/ia-study-guide/)：理解分类、标签、导航和用户心智模型。
- [NN/G：Card Sorting](https://www.nngroup.com/articles/card-sorting-definition/)：用用户的语言发现他们如何分组功能。
- [NN/G：Tree Testing](https://www.nngroup.com/articles/tree-testing/)：在画高保真页面之前，验证用户能否在导航树中找到任务。
- [Android：Settings](https://developer.android.com/design/ui/mobile/guides/patterns/settings)：低频偏好应进入设置；高频操作应靠近具体功能。

### Android / Compose 参考

- [Now in Android](https://github.com/android/nowinandroid)：完整的 Kotlin + Jetpack Compose 应用，包含 Material 3、自适应布局、设计案例、模块化和截图测试。适合建立页面骨架和统一组件。
- [Jetpack Compose Samples](https://github.com/android/compose-samples)：官方样例集合。
  - [Reply](https://github.com/android/compose-samples/tree/main/Reply)：列表—详情、自适应导航、Material 3 和主题。
  - [JetLagged](https://github.com/android/compose-samples/tree/main/JetLagged)：睡眠数据、自定义布局、图形和动画。
  - [Jetsnack](https://github.com/android/compose-samples/tree/main/Jetsnack)：自定义设计系统、布局和动画。
- [Tasks.org](https://github.com/tasks/tasks)：成熟的任务、标签、提醒和过滤器管理，适合观察大量任务的不同视角。
- [Loop Habit Tracker](https://github.com/iSoron/uhabits)：开源 Android 习惯追踪，适合观察规则、历史和长期趋势。

复制代码前需要分别检查 Apache-2.0、GPL 等许可证。Tasks.org 和 Loop Habit Tracker 更适合参考交互与组织方式，不应直接当作可随意拷贝的组件库。

### 设计与研究工具

- [Penpot](https://github.com/penpot/penpot)：开源设计协作和原型工具。
- [Penpot Libraries & Templates](https://penpot.app/penpothub/libraries-templates)：有移动导航、线框、设计系统和 token 模板。
- [draw.io](https://github.com/jgraph/drawio)：适合先画页面树、跳转关系和返回路径。
- [Mermaid](https://mermaid.js.org/)：把导航树、流程和状态机放进仓库，便于评审和版本比较。
- [indigane/cardsort](https://github.com/indigane/cardsort)：开源卡片分类工具，可用于小规模内部测试。
- [tree_test_analyzer](https://github.com/minw147/tree_test_analyzer)：开源树测试工具，用于验证信息架构的可找性。
- [Airbnb Showkase](https://github.com/airbnb/showkase)：为 Compose 组件、颜色和字体生成可搜索目录，适合后续建立组件展厅。

## 推荐实施顺序

### 第一阶段：信息架构

1. 建立功能—页面清单。
2. 将每项功能改写成用户任务。
3. 做两版导航树。
4. 用 10–20 个真实任务题目做卡片分类和树测试。
5. 确定一级入口和页面名称。

建议测试题目：

- 找到漏做的昨天习惯。
- 只修改这一次提醒。
- 查看本周项目的实际耗时。
- 给旧任务选择项目。
- 补记昨天的时间。
- 把分享来的文字先放入收件箱。
- 将一个时间块交给系统日历确认添加。

### 第二阶段：页面骨架

先重构三个最能暴露问题的页面：

1. 项目与子任务。
2. 周期任务与习惯。
3. 生活期限。

这三个页面可以验证列表、状态摘要、详情、规则/实例分离、确认操作和延期流程。

### 第三阶段：视觉系统

建立统一的：

- 页面标题和返回行为。
- 状态徽章和颜色语义。
- 列表项和卡片层级。
- 筛选、排序和搜索。
- 空状态、错误状态和加载状态。
- 确认弹窗、底部操作栏和危险操作。
- 颜色、字体、圆角、间距和图表 token。

最后再做主题、动效和品牌化视觉。页面变漂亮之前，先确保用户能找到、理解并完成任务。
