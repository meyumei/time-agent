## 小清新色板

按用户指定的 [Adobe Leonardo](https://github.com/adobe/leonardo) 思路，用目标对比度约束色阶，而非仅给颜色降低透明度。实际调用固定版本 `@adobe/leonardo-contrast-colors@1.1.0` 的 `Color`、`Theme`，以 CAM02 插值生成浅色/深色 token；参考 [官方 API](https://github.com/adobe/leonardo/blob/main/packages/contrast-colors/README.md)。

色相采用薄荷、浅紫、奶油、蜜桃等方向。每色有独立的填充、标题、次级文字和装饰色；小字保持不透明，装饰色只用于圆点和边框。标题与色块的对比度至少 7:1，次级文字至少 4.5:1。实际生成值见 [色板和测量结果](../../design/timeline-palette.json)。

同一模块关联的计划和实际共用颜色；课程按名称保持稳定，其他项目确定性取默认色。详情和活动模块编辑页可以选择预设，选择落盘，重开应用仍保留；“恢复默认”删除覆盖值。色块仍配合名称区分项目，颜色不承担唯一识别作用。

生成入口：[generate-timeline-palette.mjs](../../scripts/generate-timeline-palette.mjs)。它输出 JSON 和 `TimelinePaletteTokens.kt`，不在 Android 运行时调用，也不增加 APK 的 JavaScript 依赖。主题原有主色和深色切换继续有效。

## WakeUp 的 REA 调查与适配

使用已安装的 REA 6.5.0、本地 JADX 和 Apktool 对 WakeUp 6.5.2 APK 进行静态分析。共保存 114 条 REA 记录，详细方法、资源和原始 smali 见 `evidence/wakeup-selection-rea/REPORT.md`（本地文件，未纳入 Git）。没有运行 WakeUp 或写入其课程。

证据显示 WakeUp 为两阶段交互：先短点空白出现粉色占位块、白色加号和上下箭头；再从块或箭头按下拖动，抬手进入添加页。第二次直接点块也会进入。WakeUp 以节次换算时段，箭头原本是整体命中区域。

时间 Agent 采用分钟时间轴，因此做以下适配：

1. 点空白出现默认一小时选块，不立即写入数据。
2. 再点加号进入添加页；从块中部拖动可平移时段。
3. 上、下拖柄分别调整开始和结束，按 15 分钟吸附，最短 15 分钟。
4. 拖动松手后自动进入添加页，带入日期和起止时间。末列拖柄放在左侧。
5. 双指缩放取消当前选块，保持原缩放手势；保留原有空白长按拖选。

## 添加计划或实际

- 同一页面切换“计划 / 实际”，标题、备注及编辑过的日期时间均保留。
- 计划可新建任务并安排，也可关联已有任务；重叠时明确显示“仍然保存”。
- 实际可不关联任务；标题保存在备注首行，原备注完整保留。后续备注行重复标题不会覆盖卡片标题。
- 未来实际记录仍需确认；修改日期或时间后须重新确认。
- 保存期间防止重复提交，取消不产生实体或操作历史。

新建任务和计划沿用现有 Repository 事务及其历史规则，没有更改为一次复合撤销。数据库版本保持 v3，无 schema 变更；颜色使用独立 SharedPreferences。

## 缩放优化和证据

排查发现每帧按日期过滤提醒、反复分组冲突、已知尺寸卡片仍子组合，以及文字宽度按每个像素变动。

- 提醒按日期建立索引，仅在提醒源或时区改变时重建。
- 每日缓存冲突成员、时间边界及实际对照栏标记。
- 主时间轴直接传递已算好的卡片尺寸。
- 文字换行宽度向下取 2dp 步进，标题布局与高度变化分离；卡片外框、缩放焦点和时间坐标仍连续变化。

120 条提醒、18 步捏合的同一回归中，优化前首次读取 840 次，手势额外读取 21,840 次；优化后首次 120 次，手势额外 0 次。文字测试比较真实排版输入，不把 Compose 语义查询对象地址当作缓存或帧率证据。

这里验证的是消除重复工作和保持交互正确；没有测量手机帧率。本轮不连接手机，真机触感仍需用户安装后评估。
