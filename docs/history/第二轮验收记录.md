## 重点回归

- 原 42 项基线保留；修正后重新执行完整测试。
- 活动、任务、冲突列表和运行计时的版本核对与写入同事务完成，旧预览不能覆盖新修改。
- 取消请求会断开连接；旧请求延迟结束时不能清除新请求的等待状态，也不能递交过期结果。
- “一个半小时”正确识别 90 分钟；矛盾时长、小数时长及含糊午夜表达要求澄清，实际记录备注完整显示在预览中。
- 导入确认失败时在预览弹窗中显示原因，草稿保留，返回修正后可以重新预览并导入。
- 连续浏览未来日期后，助手查询“本周”与复盘使用正在浏览的周；复盘返回本周也会正确重置时间轴。

界面测试采用 Robolectric API 28、411 × 891 dp 配置和原生绘制，涵盖实际触摸、真实 Room 写入与页面交互。它们没有模拟手机上的语音识别效果或学校登录成功。

本轮按用户授权，通过已安装 WorkBuddy 的正常登录调用指定 `deepseek-v4.1-flash` 模型，完成两处解析/预览源码修改及只读复查；主开发流程独立审核、补失败回归并执行构建。首次工具复查达到轮数上限，后续无工具源码包复查成功。没有提取 WorkBuddy 凭据或发送用户 PDF。模型声明不替代实际测试输出。

## Lint 提示的处理

12 项提示中，8 项为固定依赖版本可更新；3 项来自 PDF 库传递依赖 Bouncy Castle 的 TLS 信任管理器类。应用源码不构造这些信任管理器，HTTPS 使用系统默认校验，WebView 证书错误直接取消；没有加入放行证书的逻辑。另 1 项建议使用 SharedPreferences 的 KTX 写法，当前显式检查同步 `commit()` 的返回值以便反馈保存失败，因此保留。

没有为消除提示而批量升级库或屏蔽安全检查。正式分发前仍需核对完整传递依赖及打包 notice，直接依赖已更新至[第三方记录](../../THIRD_PARTY_NOTICES.md)。
