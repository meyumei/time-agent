## 重点场景

1. 系统语音异步返回权限错误后，物理长按和读屏按住状态立即复位，松手不会提交失效结果。默认语音路径改用应用内置中文识别。
2. 录音状态区分准备、开启麦克风、聆听、整理和结果就绪。用户松手和采集上限都会停止采集；已有 PCM 顺序处理，模拟识别阻塞时不会丢弃队列尾部。
3. 首页顶部显示实时文字，上滑取消清除文字。最终原始文字位于助手上方，可编辑。转写和本地解析不直接写库。
4. 同音建议只提供选择：测试用中文合成语音中“停止计时”被通用模型识别成“停止进食”，“示例”也出现同音误识别。有限语法候选识别到目标指令后，用户需点击“可能想说”才采用，再确认具体修改。原始错误保留在证据中，没有把候选伪装为准确转写。
5. 五条桌面中文合成语音均产生实时中间文字，原始结果或可选指令与目标一致。验证使用 Vosk 桌面 0.3.45 与 APK 内同一个 CN 0.22 模型；Android 运行时为 0.3.75。不能据此承诺真机识别准确率。
6. 本地与云端严格协议支持整批取消示例课程：32 次内置示例实例只在确认后统一取消，一次撤销恢复；同名真实来源课程及任务保留。一条实例改变会使旧预览或整批撤销整体拒绝。
7. 真实用户 PDF、五山统一作息、Room v1→v2 迁移、全天时间轴、缩放、深浅主题和原有编辑流程纳入回归。

## 设备与外部服务边界

用户确认手机为小米／澎湃 OS，未提供确切版本。本次开发环境未连接测试手机，因此没有完成真机麦克风验收。旧版截图已证明用户设备上的 DeepSeek 请求获得响应；本轮没有读取或调用用户的 API Key。

覆盖安装后，首次使用需等待中文模型准备，并允许麦克风“仅使用时”访问。录音失败对话框可进入应用权限设置或重新准备；也请检查控制中心的麦克风开关。正式开始录音前按钮显示“开启麦克风”，麦克风成功启动后才显示“松开识别”。

官方教务真实账号导入仍沿用此前未验收的边界，PDF 导入可使用。证据汇总为 `outputs/v0.3.1/verification.json`、`build.log`、`native-package.json` 和 `offline-asr.json`。
