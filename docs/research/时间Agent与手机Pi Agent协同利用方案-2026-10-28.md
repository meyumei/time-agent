# 时间 Agent 与手机 Pi Agent 协同利用方案（旧方向）

> 方向已按用户澄清修正：用户的目标是让时间 Agent 内部的大肥鱼成为真正的管家 Agent；Pi Mobile 只用于研究 Agent 实现，DSH 只作为插件化架构参考。请以[时间Agent内嵌大肥鱼管家与DSH方案-2026-10-28.md](时间Agent内嵌大肥鱼管家与DSH方案-2026-10-28.md)为准。

- 日期：2026-10-28
- 当前时间 Agent：`0.11.0 / code17`，Room `v11`
- 当前手机 Pi Mobile：`0.2.14 / code20`
- 目标：利用现有手机 Pi Agent，优化时间 Agent 的管家 Agent，而不是重复建设两套 Agent 运行时
- 本文性质：现状审计与集成方案，本轮未修改产品源码

## 1. 结论先行

手机上的 Pi Agent 不应该替代时间 Agent 的数据库和执行规则。最合理的分工是：

```text
Pi Agent = 开放式思考、复杂分析、资料整理、项目工作、工具执行
时间 Agent = 时间账本、提醒、计划、实际记录、健康边界、撤销和最终裁决
原创鲸鱼管家 = 两者之间的状态与解释层
```

时间 Agent 负责“什么是真实发生的、什么时候发生、能不能写入”；Pi 负责“怎么分析、怎么拆解、怎么提出方案、怎么完成需要工具的开放任务”。

第一阶段不建议把 Pi 的 Node 运行时、Pi CLI 和整套工作区打进时间 Agent。当前 Pi Mobile 已经是一个独立的内嵌运行时，APK 约 `68.26 MiB`，另有约 `31.99 MB` 的运行时压缩包；重复打包会放大安装体积、后台进程、网络配置、模型认证和权限维护成本。

## 2. 手机 Pi 当前已有什么

本机在 2026-10-28 本轮检查中曾通过 ADB 识别到：

- 设备型号：`2407FRK8EC`，Android `16`；
- 包名：`com.pimobile.app`；
- Pi Mobile：`0.2.14 / versionCode 20`；
- Pi CLI：运行时包内 `@earendil-works/pi-coding-agent 1.4.0`；
- Pi Agent 已经内嵌在 Pi Mobile 的应用沙箱，不再必须依赖 Termux；
- 应用拥有前台服务能力，用于维持内嵌 Node 和长任务；
- 已有工具审批扩展，文件修改和高风险命令可以经过手机端审批；
- Pi 会话、模型配置和扩展位于 Pi Mobile 私有沙箱；
- 现有后端默认监听 `127.0.0.1:8787`；
- 后端提供 HTTP + SSE 桥接，底层仍然调用真实 Pi 的 JSONL RPC。

本轮后续读取时 ADB 设备已经断开，因此“当前手机此刻是否在线”没有继续确认。上面版本和包状态来自本轮稍早的设备读取及已有验收文档，不把断线后的状态当成新的实时证明。

## 3. Pi Mobile 的可复用能力

### 3.1 真实 Agent 运行时

Pi Mobile 不是一个只显示聊天页面的壳。它包含：

- Pi CLI；
- Node 运行时；
- 会话文件；
- 模型配置；
- 工作区；
- HTTP + SSE 后端；
- Pi RPC JSONL 桥接；
- 工具调用状态；
- 扩展 UI 请求和审批响应。

因此，它可以作为时间 Agent 的“复杂工作台”或“外置执行脑”，但应通过受控协议合作。

### 3.2 流式状态

Pi 后端已经有事件总线和 SSE：

```text
agent_start
tool_call / tool_result
extension_ui_request
compaction_start / compaction_end
agent_settled
backend_snapshot
```

这些事件非常适合驱动原创鲸鱼管家的状态：

| Pi 事件 | 管家表达 |
|---|---|
| 后端启动、等待输入 | Idle |
| `agent_start` | Thinking |
| 工具调用进行中 | Working |
| `extension_ui_request` | WaitingConfirmation |
| `agent_settled` 且成功 | Done |
| 进程异常退出或请求失败 | Error |
| 没有主动任务且处于安静时段 | Resting |

时间 Agent 自己也应发布同一套 `ButlerState`，这样管家形象不需要知道底层到底是本地解析、DeepSeek 请求还是 Pi。

### 3.3 工具审批门

Pi Mobile 的审批门可以借鉴为时间 Agent 的统一安全交互：

- 只读操作自动放行；
- 文件修改和外部写操作弹窗确认；
- 高风险命令每次确认；
- 没有 UI 或审批异常时 fail-closed；
- 用户可以拒绝，Agent 必须收到明确的阻断原因；
- 审批结果进入事件日志。

这套思想可以迁移到时间 Agent：

```text
读取日程/查询空档       -> 自动执行
创建普通任务             -> 可按用户设置自动执行
改动未来计划             -> 预览后确认
删除记录/批量取消        -> 强制确认
读取敏感健康数据         -> 单独授权
向 Pi 派发外部工具任务   -> 显示范围和结果，必要时确认
```

## 4. 推荐的协同边界

### 4.1 时间 Agent 是事实源

时间 Agent 应继续保存：

- 任务、计划、实际记录；
- 提醒和周期规则；
- 用户明确确认的个人约定；
- 项目归属和统计来源；
- 撤销、重做和操作历史；
- 主动建议的来源、有效期和用户动作。

Pi 不应直接写入时间 Agent 的 Room 数据库，也不应自行生成实际记录、补打卡、修改项目归属或改变健康结论。

### 4.2 Pi 是复杂工作源

Pi 适合处理：

- 把一个目标拆成多个行动步骤；
- 阅读工作区文件并整理资料；
- 生成学习计划草案；
- 分析项目进度和阻塞；
- 研究工具、代码或课程资料；
- 执行用户明确授权的文件操作；
- 对一周计划提出复盘建议；
- 为管家生成更自然的解释和对话草稿。

Pi 输出的“时间动作”必须回到时间 Agent 进行校验：

```text
Pi 提出方案
  -> 时间 Agent 检查任务 ID、时间冲突、个人约定和敏感边界
  -> 生成预览
  -> 用户确认或按低风险策略自动执行
  -> 时间 Agent 写入 Room 和操作历史
  -> Pi 只收到执行结果摘要
```

### 4.3 鲸鱼管家是统一外观

管家不应只显示 Pi 的状态。它应订阅两个来源：

```text
时间 Agent 状态事件
Pi Mobile 状态事件
             |
             v
      ButlerState 聚合器
             |
             v
     原创胖鲸鱼 / 鲸尾管家
```

优先级可以沿用大肥鱼的思路：

```text
等待用户确认 > 错误 > 时间 Agent 执行中 > Pi 工具工作中
> 思考 > 完成短展示 > 空闲
```

当 Pi 正在读文件时，鲸鱼可以表现为“翻资料”；当时间 Agent 等待用户确认时，应立即切换成“请你决定”，不能继续显示 Pi 的忙碌动画掩盖待处理事项。

## 5. 三种集成方式

### 5.1 方式 A：应用间显式交接

这是第一阶段最推荐的方式。

时间 Agent 生成一份脱敏的任务包，用户点击“交给 Pi”：

```json
{
  "schema": "timeagent.pi_handoff.v1",
  "requestId": "local-id",
  "goal": "整理本周数字信号处理复习计划",
  "timeConstraints": [
    {"start": "2026-10-29T19:00:00+08:00", "end": "2026-10-29T21:00:00+08:00"}
  ],
  "knownTaskIds": ["task-id"],
  "constraints": ["周四晚不安排超过90分钟的连续学习"],
  "privacy": {"health": "excluded", "privateChats": "excluded", "secrets": "excluded"}
}
```

Pi 返回的是方案或结果文本。时间 Agent 不直接信任文本中的动作，而是重新解析、预览和确认。

优点：

- 不需要让两个 App 互相访问私有数据库；
- 用户明确知道什么时候把任务交给 Pi；
- 容易审计和撤销；
- 失败时不影响时间 Agent 的核心记录。

缺点：

- 自动化程度较低；
- 需要增加分享/导入或复制交接入口；
- Pi 的结果回到时间 Agent 时需要一次解析。

### 5.2 方式 B：本机 HTTP + SSE 协同

Pi Mobile 当前后端默认是 `127.0.0.1:8787`，已有：

- `/api/health`
- `/api/agent/state`
- `/api/agent/messages`
- `/api/agent/prompt`
- `/api/agent/steer`
- `/api/agent/follow-up`
- `/api/agent/abort`
- `/api/agent/ui-response`
- `/api/sessions`
- `/api/events`

理论上，时间 Agent 可以通过 Android 网络请求访问手机回环地址，并使用 Pi Mobile 的 HTTP/SSE 接口。

但当前接口设计主要服务 Pi Mobile 自己的前端，存在几个阻塞点：

- 没有面向第三方 App 的独立认证令牌；
- `127.0.0.1` 并不等于“只有时间 Agent 能调用”；
- `/api/agent/prompt` 是开放式自然语言入口，不是时间动作的强类型协议；
- Pi Mobile 的会话和工作区是私有沙箱，时间 Agent 不应直接读写其文件；
- 直接让 Pi 访问时间 Agent 的全量数据会扩大隐私面；
- Pi 运行时升级时接口兼容性需要单独维护。

因此方式 B 适合第二阶段，前提是新增：

1. `timeagent.pi_bridge.v1` 版本化接口；
2. 每次安装随机生成的本地 token；
3. 只开放有限的 prompt 和状态接口；
4. 请求 ID、超时、取消和审计日志；
5. 通过摘要传输，不开放 Room 数据库；
6. Pi 返回结构化方案，不直接执行时间写操作；
7. 断线时退回应用间显式交接。

### 5.3 方式 C：把 Pi 直接内嵌到时间 Agent

不建议作为近期路线。

Pi Mobile 已经证明内嵌 Node + Pi 可行，但它也带来：

- 约 68 MiB 级别的 APK 运行时；
- 独立的模型认证和会话目录；
- 前台服务和长期进程；
- 工具审批、文件沙箱和升级包；
- Node、原生库和 TLS 证书维护；
- 时间 Agent 自己的 Room、提醒、健康权限和动画体系。

将两者合并后，任何一方的升级都会影响另一方。除非以后要做“一体化离线工作站”，否则应保持 Pi Mobile 为独立 Agent 工作台。

## 6. 最值得立刻利用的四件事

### 6.1 直接利用 Pi 的“复杂任务能力”

时间 Agent 当前 DeepSeek 协议适合把自然语言转换成有限时间动作，优点是安全和可验证；它不适合阅读大量文件、长时间研究或执行多步开放任务。

可以新增一个低风险入口：

```text
“把这件事交给 Pi 分析”
```

时间 Agent 只发送：

- 用户目标；
- 必要的时间约束；
- 已确认的相关任务摘要；
- 明确排除的敏感信息；
- 输出格式要求。

Pi 返回：

- 计划草案；
- 需要用户确认的问题；
- 参考资料摘要；
- 建议创建的任务列表。

最后仍由时间 Agent 预览和执行。

### 6.2 利用 Pi 的工具状态驱动管家形象

这是最容易产生产品感知的能力。时间 Agent 不需要复制 Pi 的工具执行能力，只要订阅或接收：

- 当前任务名；
- 当前工具；
- 工具目标；
- 是否等待用户确认；
- 是否成功；
- 错误摘要。

鲸鱼表现可以从“思考”升级为更有信息量的状态：

- 翻资料；
- 写计划；
- 等你点头；
- 正在整理；
- 已整理完成；
- 这一步失败了。

### 6.3 借鉴 Pi 的审批门

时间 Agent 目前已有强类型 action、预览和撤销；可以再借鉴 Pi 的“工具调用前审批”：

- 将 `requiresConfirmation` 从单个命令扩展到动作风险等级；
- 把每次确认记录为操作事件；
- 让拒绝成为正常结果，而不是异常；
- 对批量修改、删除、敏感数据读取单独提高门槛。

### 6.4 利用 Pi 做离线复盘工作台

时间 Agent 可以在用户主动打开时导出脱敏摘要给 Pi：

- 本周计划完成率；
- 实际记录和计划的偏差；
- 被推迟或取消的任务；
- 用户明确确认的约定；
- 未完成原因的用户输入。

Pi 负责提出复盘问题和下周建议。时间 Agent 负责把用户确认后的内容转成任务、计划或个人约定。

## 7. 不应交给 Pi 的事情

- 直接写 Room 数据库；
- 自动补写周期任务实际记录；
- 从历史记录推断旧任务的项目归属；
- 自动删除或静默替换长期记忆；
- 绕过时间 Agent 的冲突检查；
- 自动读取健康原始数据；
- 自动读取私人聊天、通讯录或截图；
- 保存时间 Agent 的 API key、支付凭据或其他秘密；
- 直接改变提醒权限、无障碍、后台权限或安装应用；
- 用 Pi 的自然语言回复代替时间 Agent 的最终操作结果。

## 8. 推荐路线

### 阶段 1：交接卡片与状态占位

不改 Room。

产出：

- “交给 Pi 分析”入口；
- 脱敏 `PiHandoffPacket`；
- 返回结果的人工复制/导入；
- 管家状态枚举和事件模型；
- 应用内原创鲸鱼占位图。

验收：

- 发送给 Pi 的内容不包含 API key、健康原始数据和私人聊天；
- Pi 返回结果不会自动改时间 Agent 数据；
- 用户可以取消交接；
- Pi 工作中、等待确认、完成和错误都能映射到管家状态。

### 阶段 2：本机受控 Bridge

在 Pi Mobile 和时间 Agent 之间增加版本化、带 token 的本机接口。

建议只支持：

```text
POST /bridge/v1/analyze
GET  /bridge/v1/runs/:id
POST /bridge/v1/runs/:id/cancel
GET  /bridge/v1/events
```

`analyze` 只收脱敏任务包；返回方案草案和结构化建议，不接受直接写入时间 Agent 的命令。

### 阶段 3：统一主动管家

时间 Agent 统一负责：

- 安静时段；
- 每日主动预算；
- 去重和冷却；
- 用户确认；
- 通知；
- 审计；
- 撤销。

Pi 只作为一个可调用的分析执行器，不能自行决定什么时候打扰用户。

### 阶段 4：原创胖鲸鱼

把 Pi 和时间 Agent 的状态聚合成一个原创角色：

- 思考；
- 翻资料；
- 写计划；
- 等待确认；
- 执行时间动作；
- 完成；
- 出错；
- 休息。

角色资产自建，不能打包现有大肥鱼素材或 DeepSeek 商标。

## 9. 最终推荐

当前最适合的产品形态是：

```text
时间 Agent：个人时间数据库与本地管家
Pi Mobile：复杂任务工作台与工具 Agent
DeepSeek：受控的语言理解和分析模型
胖鲸鱼管家：统一状态、提醒和情绪表达
```

最先做的功能不是“把 Pi 塞进时间 Agent”，而是：

1. 时间 Agent 增加“交给 Pi 分析”；
2. 生成脱敏任务包；
3. Pi 返回计划草案；
4. 时间 Agent 预览、校验、确认、写入和可撤销；
5. 两边的状态统一由原创鲸鱼展示。

这条路线能利用现有 Pi 的真实能力，同时保留时间 Agent 的数据可信度和安全边界。
