# 时间 Agent 与大肥鱼：统一启动方案

日期：2026-10-28

本文收拢本窗口的需求、修正和两份 DS 4.1 调研。后续按本文启动；此前方案保留为资料，出现分歧时以这里的取舍为准。

开发执行的模块、依赖顺序、任务分工和交付标准已收敛到[内置大肥鱼开发方案](../engineering/时间Agent内置大肥鱼-开发方案-2026-10-28.md)。以该方案的 P0 运行原型与并行页面线框作为第一轮任务。

## 1. 产品目标与起步决定

时间 Agent 负责帮用户组织生活和时间，大肥鱼负责持续陪伴、交流和帮助办事。QQ、B站和未来的 App 入口对应同一个角色，经历能够连接起来。

**采用“选择性借用 DSHA 源码，在时间 Agent 内承载 DSH 与所选养鱼插件”的目标方向。去掉对独立 DSHA App 的运行依赖，保留中央输入和原生业务页面。先明确具体鱼插件与取材范围，同时整理页面骨架。**

用户补充要求尽量减少外部 DSHA 依赖。完整取舍见[内置大肥鱼：源码复用与依赖取舍](时间Agent内置大肥鱼-源码复用与依赖取舍-2026-10-28.md)。此前“两款 App”路线保留为体验参考，不再作为当前目标形态。

用户补充的具体宿主为 [DSH-APP/DSHA](https://github.com/DSH-APP/DSHA)。两项 WorkBuddy CLI DS 4.1 研究已读取其 README、插件文档、端口说明和 AndroidManifest 等材料，确认它在手机本地承载 DSH；当前尚未安装运行或验证养鱼插件。

### 鱼住在哪里，用户在哪里看见它

- 目标运行位置：时间 Agent 自己管理的内部运行环境，复用必要宿主代码承载 DSH 和所选养鱼插件。
- 人格、记忆和主动活动：跟随这一套角色和插件配置。
- 时间 Agent：提供业务页面、时间数据、中央语音／自然语言输入、鱼的表现与交流入口，以及内部运行模块。
- QQ、B站：按手机端所选插件的实际能力逐项连接，归属于同一角色。

因此用户目标是安装并使用时间 Agent 即可，不需要另开 DSHA。保留 DSH 运行时是为了复用插件；它的包体和维护仍然存在。具体裁剪、插件手机兼容和原生会话连接需要围绕选中的鱼确认。

### 长期运行是什么意思

DSHA 的文档和清单包含前台服务、唤醒锁权限、开机广播以及看门狗等机制，具备承载长期运行服务的设计。实际后台持续性仍需在目标手机体验；不能把这些机制表述成“永远不会被系统回收”。人格与记忆持久保存、进程持续在线、模型推理是三件事：人格可以长期保留，进程停止期间主动活动暂停；配置云端模型时，推理依然依赖模型服务。

这段说明用于回答运行位置和长期运行问题，不新增规则引擎或防御性开发。

当前工作是产品整理与原型设计。人格、性格、称呼、语气、形象和动画由用户后续提供；页面布局可以先使用角色占位。

## 2. 本窗口已确定的要求

| 用户想法 | 统一决定 |
|---|---|
| 功能很多，不知道怎么归类 | 一级入口按用户当前要做的事组织：今天、计划、复盘、管家 |
| 中间原有的语言输入功能继续保留 | 底栏中央保留语音与自然语言输入，是四个页面共享的快捷操作入口 |
| 主页面和子页面简陋、割裂 | 一起整理列表、详情、编辑、返回和完成后的去向，建立共享页面样式 |
| 大鱼在 App 里是一个长期角色 | 鱼有共同人格和经历，时间 Agent 是它帮助主人生活的一处入口 |
| 鱼能去外部平台主动活动 | 优先复用已实现的浏览、评论、回复、动态能力，让鱼自行决定参与和表达 |
| 像朋友一样带回有趣内容 | 使用自然闲聊，来源链接随话题出现；聊天不变成视频目录 |
| 多平台是同一个大肥鱼 | 共用角色与记忆；平台会话可分别存在，长期经历连接起来 |
| 发作品和回复由鱼自己决定 | 采用现成插件的自主活动方式；逐条审批不作为日常交流流程 |
| 对话语气、人格和形象以后提供 | 本阶段只确定交流方式和页面位置，不预设口头禅、幽默感或外观 |
| QQ 已有实现，可能更方便 | QQ 可作为同一条鱼的交流通道；具体是否先用 QQ，取决于所选手机插件的实际支持 |
| 手机 DSHA 已有宿主，但希望减少外部依赖 | 挑选其必要源码整合进时间 Agent，保留 DSH 运行时与所选鱼插件 |
| 资料研究只用 DS 4.1 子代理 | 使用 WorkBuddy CLI 分工研究，沿用已经取得的两项结果 |
| 不要防御性工作和编程 | 起步聚焦功能整理、页面设计、现成方案体验和明确的连接路线 |

## 3. 功能归属：从哪进入，完成后回哪里

| 能力 | 主入口 | 日常使用方式 | 相关入口 |
|---|---|---|---|
| 今日任务、逾期、临近截止 | 今天 | 看接下来做什么，开始或完成 | 计划里的任务与期限详情 |
| 课程、日程、计划时间块、实际记录 | 今天 | 在时间轴上安排、计时、补记 | 复盘看投入与趋势 |
| 项目、阶段、子任务 | 计划 | 在项目中确定下一步，再排进今天 | 今天展示要执行的任务 |
| 每周目标 | 计划 | 设定本周目标与投入 | 复盘查看进展与原因 |
| 习惯与周期任务 | 计划 | 管规则和重复安排 | 今天完成本次，复盘看历史 |
| 生活期限、生日、续费、归还 | 计划 | 按时间组织，进入详情处理或延期 | 今天展示临近事项 |
| 想法、笔记、外部分享、附件、提取文字 | 计划的收件箱 | 先收集，再归项目或转任务 | 项目详情查看关联资料 |
| 开始训练、训练模板、动作库、3D 肌群 | 今天的训练入口 | 从模板开始，进行训练，结束记录 | 复盘查看训练记录和趋势 |
| 睡眠、运动与健康数据 | 复盘 | 看趋势和具体记录 | 今天看最近摘要与快速记录 |
| 周报、项目复盘、历史问答 | 复盘 | 从结果回到具体任务和记录 | 管家协助解释和讨论 |
| 回复副驾 | 管家 | 围绕要回复的事情起草 | 需要时间安排时关联计划 |
| 人格、记忆、外部平台与养鱼互动 | 管家 | 了解和联系这条鱼，管理它的入口 | 内部运行模块承载同一角色，QQ 按可用插件接入 |
| 导入、导出、备份、同步、账号、外观 | 设置 | 低频管理 | 管家页次级入口 |

同一能力可以在多个场景有入口，但指向同一份内容。例如今天完成一项项目任务，计划里的项目和复盘里的进度一起反映结果。

### 底栏中央输入入口

底栏布局为：**今天 / 计划 / 中央语音输入 / 复盘 / 管家**。中央按钮是快捷动作，四个一级页面仍然保留。

按住说话或输入自然语言，可以记录时间、收集想法、安排任务、查询日程。QQ 承载日常私聊，并不替代这个 App 内操作入口。后续采用现成手机 Agent 宿主时，复杂理解和规划可以交给同一条鱼，时间 Agent 继续显示处理结果和对应页面。

## 4. 四个主页的第一版骨架

### 今天：打开就知道接下来做什么

- 首屏：日期、当前事项、下一件事。
- 主体：时间轴与今日待办，明确区分计划和实际。
- 高频操作：快速记录、开始计时、安排任务、开始训练。
- 鱼的位置：一处紧凑的简报或联系入口；形象使用占位。

### 计划：把事情组织清楚

- 首屏：项目、全部任务、习惯周期、生活期限、收件箱。
- 选定分区后显示对应内容，列表负责浏览，详情负责推进。
- 项目详情呈现目标、下一步、任务、周目标和资料。
- 习惯默认看本次和近期执行，再进入规则编辑。

### 复盘：看发生了什么，下一步怎么调整

- 首屏：本周投入、完成情况、项目进展。
- 主体：时间、项目、健康和训练的趋势与明细。
- 点进数字可以找到对应记录；围绕具体结果向鱼提问。

### 管家：和同一条鱼建立长期联系

- 首屏：鱼的角色占位、最近状态、同一角色的联系入口。
- 次级内容：共同记忆、平台经历与连接、养鱼互动、设置。
- 共享内部运行模块中同一角色的对话与记忆；App 与 QQ 的具体入口按所选插件能力落地。
- 外部经历以话题延续，不建立“视频推荐大厅”。

## 5. 先统一哪些子页面

先画项目、周期任务、生活期限三组页面，覆盖三种典型操作逻辑：

| 页面组 | 页面内容 | 要走通的过程 |
|---|---|---|
| 项目 | 项目列表、项目详情、任务详情、选择时段 | 找项目 → 选下一步 → 排进今天 → 开始 → 完成 → 看进展 |
| 周期任务 | 本次列表、实例详情、规则编辑 | 找到本次 → 完成或调整本次 → 回到今天；修改以后进入规则 |
| 生活期限 | 按日期分组、详情、延期 | 看临近 → 处理或延期 → 返回原分组 |

共享的页面语法：标题和范围在顶部；最重要的状态与下一步靠前；主内容居中；主操作清楚；低频设置进入次级位置。

视觉参考沿用已有调研：Reply 学列表与详情，JetLagged 学睡眠趋势，Tasks.org 学任务视角，Loop 学习惯记录。当前阶段选定这些用途即可，页面的色彩、字体与鱼的品牌表现待下一轮视觉设计收敛。

## 6. 同一条鱼如何组合

```text
             时间 Agent 内部：大肥鱼、人格、共同记忆和插件
                                  |
              +-------------------+-------------------+
              |                   |                   |
           QQ 主人私聊          B站活动         时间 Agent 能力适配
        按手机插件支持接入  按手机插件支持接入  日程、项目、记录、复盘
                                                      |
                                             中央输入与 App 内交流
```

借用 DSHA 的必要手机运行层，由时间 Agent 管理。SurfCore 继续作为“多平台同一条鱼”的结构参考，但它的 Windows、SnowLuma 和桌面组件不能直接推定可在手机运行。保留 DSH 插件运行基础，具体养鱼插件及其依赖仍要核实手机兼容性。第二个视频的 AstrBot 用来参考聊天配置与现成插件；第三个视频用来参考人格卡配置。

沿用同一角色，不在时间 Agent、QQ 和 B站分别重新配置三套独立人格与经历。原生界面、中央输入、内部会话和业务工具之间的连接属于后续适配工作，当前尚未实现。

App 内养鱼互动继续保留产品位置。喂养、装扮与共同活动的具体内容，等用户提供形象与性格后设计。

## 7. 从现在开始的顺序

### 第一项：完成页面结构设计

这项马上可以开始，无需等待人格素材。

交付物：一张完整导航图、四个主页线框、三组子页面流程。用“安排任务、补记时间、调整本次习惯、处理期限、整理想法、开始训练”六件日常事情逐项走一遍。

完成标志：用户可以从首页找到入口，理解当前页面，完成事情后回到合适位置；每项现有功能都有去处。

### 第二项：确定所选鱼与源码取材范围

选用手机运行环境兼容的人格、记忆和主动活动插件。围绕它列明借用哪些 DSHA 源文件、保留哪些运行组件、原生界面如何连接会话，再按实际支持连接 QQ 和 B站。

交付物：一张具体取材与连接图，随后才进入最小实例。体验时看“交流是否自然、记忆能否延续、手机后台活动如何”。多平台部分继续检查“外部见闻能否接着聊、是否认得同一个主人”。

这一步属于后续部署工作；本轮整理没有安装、登录或发送消息。

### 第三项：补入用户的人格与形象

用户提供素材后，统一配置共同角色，完善管家页与养鱼互动。页面结构设计和现成体验不因素材暂缺而停住。

### 第四项：选择第一次时间 Agent 连接

第一个体验目标定为：**在时间 Agent 中央输入说“看看我今天安排得怎么样”，同一条鱼能根据 App 的真实日程回应。** QQ 后续接入时也能围绕同一角色的经历交流。

先将一个日常问题连接起来，再扩展安排任务、项目跟进和复盘。具体接线留到页面与现成鱼体验明确后决定。

## 8. 对旧方案的统一取舍

| 旧表述 | 现在采用的方向 |
|---|---|
| 优先开发完整 ButlerKernel、自主规则内核 | 优先复用必要 DSHA 源码、DSH 运行基础与手机兼容鱼插件 |
| 先做 App 内完整长期聊天或只用 QQ | 保留中央输入与 App 内交流方向，QQ 作为可接入的现成通道 |
| 电脑宿主或独立 DSHA 承载鱼 | 目标改为时间 Agent 内部运行，DSHA 提供可借鉴和复用的源码 |
| 视频卡片、推荐理由、成组操作按钮 | 自然话题与连续闲聊，来源链接随需要出现 |
| 外部评论、动态逐条人工批准 | 鱼按现成插件方式自主活动 |
| 先定原创胖鲸鱼或预设称呼与语气 | 统一等待用户提供角色设定与视觉参考 |
