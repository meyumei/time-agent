# 时间 Agent 内置大肥鱼：源码复用与依赖取舍

日期：2026-10-28

## 当前建议

用户希望减少对独立 DSHA App 的依赖，并借用已有代码形成自己的产品。本轮建议采用**选择性内置**：把需要的手机宿主能力与所选 DSH 养鱼插件整合到时间 Agent，原生页面和中央输入继续由时间 Agent 提供。

这是对前一版“手机安装两款 App”的修订。当前只完成源码研究和产品取舍，没有开始复制代码、安装运行时或更改产品源码。

## 三种依赖要分清

| 层次 | 当前取舍 | 对用户意味着什么 |
|---|---|---|
| 独立 DSHA App | 计划去掉 | 使用时只需打开时间 Agent，由它管理自己的运行环境 |
| DSH 运行时 | 为复用 DSH 插件而保留 | 运行时成为时间 Agent 内部的一项组件，版本由本项目决定 |
| 所选养鱼与平台插件 | 挑选复用并适配 | 人格、记忆、主动话题和外部活动继续来自同一角色 |

源码复用使我们获得修改权和版本控制权，也将所借用模块的维护交给本项目。它减少对另一个 App 的运行依赖，并不会自动消除运行时的体积和维护工作。

## 为什么不只复制界面或前台服务

DSHA 的 Android 层主要负责运行环境、进程和界面承载；鱼的人格、记忆与活动能力来自 DSH 及其插件。复制界面、看门狗或前台服务，不会同时得到完整的鱼。

可以复用的代码范围应覆盖真正需要的链路：准备运行环境 → 启动 DSH → 加载所选插件 → 连接时间 Agent 的对话和业务能力。

## 选择性内置的组成

```text
时间 Agent
  ├── 原生业务页面：今天、计划、复盘、管家
  ├── 中央语音／自然语言输入
  ├── 大鱼的显示与交流入口
  ├── 内部 Agent 运行模块
  │     ├── 借用并适配 DSHA 必要的环境与进程管理
  │     ├── DSH 运行时
  │     └── 所选人格、记忆、主动活动与平台插件
  └── 时间管理能力：日程、任务、项目、记录、复盘
```

这是一张目标架构图。原生界面与 DSH 会话的连接、具体插件的手机兼容性，尚未实现或验证。

## 从 DSHA 取哪些内容

| 模块 | 取舍 | 当前证据 |
|---|---|---|
| 容器与运行时启动 | 保留研究与复用范围 | `ContainerRuntime`、`RuntimeLauncher`、`ProotBootstrap` 等负责手机环境启动 |
| 服务与进程生命周期 | 按实际依赖抽取 | `HarnessService`、`HarnessController`、`WebProcessManager` 等参与管理 |
| DSH 启动参数和状态回传 | 复用必要部分，再接本项目界面 | `WebLaunchCommand`、`DshAuthUrl`、`WebOutputSession` 等已有实现 |
| 插件加载 | 围绕选定的鱼接入 | 不需要一开始复制完整插件商店和全部管理界面 |
| 人格与记忆 | 复用所选鱼插件的实现 | 这些能力不等于 DSHA 的 Android 外壳 |
| 完整终端、局域网网页、虚拟屏、ADB 工作台、独立更新界面 | 当前产品未提出这些需求 | 先不纳入起步功能；真正抽取时仍需查看传递依赖 |
| Windows 专属组件 | 不直接搬入手机 | SurfCore 的 Windows/SnowLuma 组件不能因代码可见就推定手机兼容 |

DSHA 的现有实现包含 Ubuntu、Node、DSH 及配套资产。选择性内置不意味着可以立即缩成一个很小的库，实际裁剪范围需要围绕所选插件确定。

## 对比三个方向

| 路线 | 能否摆脱独立 DSHA App | 现成 DSH 插件复用 | 当前判断 |
|---|---|---|---|
| 外部 DSHA + 时间 Agent 适配 | 否 | 在 DSHA 中接入 | 适合先体验，不作为用户当前偏好的最终形态 |
| 选择性内置必要宿主 + DSH + 所选插件 | 是 | 保留运行时基础，逐项适配 | 推荐方向 |
| 全部改为 Kotlin 原生 Agent | 是，也能去掉 DSH 运行时 | 需逐项移植或重做 | 可作为另一种长期取舍，不作为本轮起步任务 |

原生页面与内部运行时可以作为不同模块组合。读取 DSHA 目前使用 Web UI，并不足以证明自有原生界面永远无法连接 DSH；但也没有证据表明已有一个可直接接上的完整原生客户端接口。因此，这一连接是待确认的工程点。

同理，使用同版本 DSH 不能直接推导全部插件百分之百兼容。插件可能依赖 Windows、原生模块或额外服务，需要以选中的具体插件为对象判断。

## 代码可以借用吗

DS 4.1 读取到 DSHA 自有代码采用 MIT，允许按相应许可复用与修改，分发包含这些代码时保留版权与许可声明。DSHA 随包第三方资产各有来源，不能把整个 APK 一概当作 MIT 代码复制。

实际取材时区分自有源码和第三方运行组件即可。本轮没有据此开展额外的防御性开发。

## 下一步做什么

1. 先选定真正要复用的一套鱼：人格、记忆、主动活动，以及需要的外部平台能力。
2. 做一张以它为中心的取材图：复用哪些源文件、保留哪些运行组件、哪些能力要适配。
3. 明确中央输入与同一条鱼之间的会话连接方式。
4. 将上述取材图与四个主页、三组子页面原型合并成一份实施稿，再进入代码工作。

首个体验目标保持不变：在时间 Agent 中央说“看看我今天安排得怎么样”，由 App 内同一条鱼结合真实日程回应。
