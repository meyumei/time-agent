# T4.1 任务编辑器的子任务、提醒与附件

日期：2026-11-05。影响 L03、L05、L07、L12；关联 L01 和 T2.5。

## 实际实现

- 编辑器显示子任务进度、长按拖动柄排序及等价上/下移动操作。排序使用测量行高，保存在按父任务隔离的显示偏好中，不修改业务实体。原有一级父子任务约束保留。
- 可添加新子任务、移除未保存的子任务、打开已有子任务。打开子任务时保留父编辑器草稿；已有子任务的内容及完成状态由自身编辑器/既有操作管理。新子任务标题即使尚未点“添加”，也纳入主表单保存与离开草稿判断。
- 任务提醒显示送达状态及原重复配置，支持新增、调整日期时刻、关闭和移除。已有提醒的来源、版本、秒/毫秒及重复配置保留；送达元数据变化不会被当成编辑，避免无故重建重复链。新设过去时刻保存为关闭状态并提示，不安排补发。
- 附件可选择当前任务附件及未关联附件，提供图片缩略图、名称/类型/大小、搜索与取消关联。取消关联不删除原件，不自动抢占其他条目的附件；选择失效时明确提示。
- 顶部“安排时间”显示时间段字段，任务、子任务、提醒、附件关联与可选新日程由一次 WriteTaskDetails 保存。新建关联条目使用稳定 ID，重复请求仍由 command_log 处理。
- TaskLinkedDetails 核对提醒完整所见版本集合、已关联附件集合及所有实际涉及附件的版本。关联被他处修改或所选文件已删除时，整个命令拒绝写入。提醒增删经过现有 ReminderInstanceRepository，派生提醒实例也进入同一历史组；附件变更不触碰磁盘原件。

主库仍为 v22，无 schema 变更。任务完成不产生实际记录。业务历史仍复用 CommandExecutor 的事务、幂等及整组撤销，不创建第二套执行或重复引擎。

用户明确授权前端工作可交给 Claude/Argon。实际调用本机 Antigravity CLI：

返回未包含可独立确认的实际模型 ID 或实际 effort，均记 null；不能把请求值当作服务端实际值。两个任务仅得到隔离的 UI 参考源码和接口契约；主代理控制共享命令、实体、数据访问与最终集成。没有对外传送私人数据库、健康信息、聊天、Key 或备份。

用户要求暂停全部测试与手机操作。本任务没有执行单测、Node、迁移/仪器/设备/性能测试或 lint 分析，没有安装、卸载、清数据或操作手机。编译不是事务或真机验收。

## 尚未执行的验收

1. 不同字号和不同高度子任务行的长按拖动、取消拖动、上/下移动；重启后顺序；子任务标题未点添加时保存；父编辑器打开子编辑器后继续草稿。
2. 新建任务并添加子任务、提醒、附件和日程，一次保存与整次撤销/重做；同 requestId 重放只保存一次，完成不生成实际记录。
3. 编辑期间在另一入口新增/移除提醒、取消附件关联、修改归属后，提交旧表单应全部拒绝且没有部分写入。
4. 提醒首发/后续重复/稍后实例与手工关闭、编辑过去时刻、送达元数据更新后只改任务标题的行为；任务已完成/删除时明确失败。
5. 附件原件缺失、OCR 草稿、取消关联后原件与其他条目不变；200% 字体、TalkBack、配置/进程恢复、无 Key/运行时停止。

## 保留的缺口与待决项

- 本批没有补普通任务与周期规则之间的转换或直接在任务表单修改周期范围。现有实例 ID/快照校验强制绑定生成任务 ID；不能通过复制原任务冒充“重复已完成”。此入口及首实例身份处理仍需继续核对规格和现有引擎。
- 提醒重复间隔/次数仍在原重复配置入口编辑，本任务只显示并保留原配置。
- 附件 8MiB/12MiB 与规格大于 20MB 提示、备份 v1 上限的冲突未作产品决定，本批没有改任何容量限制。
- 所有设备、数据往返和真实手势验收保持暂停；阶段 2–5 仍未全项完成。
