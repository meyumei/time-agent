# T1.5 鱼工具、本地写入与提醒命令接入

日期：2026-11-02（Asia/Shanghai）。分支：`codex/t1.5-tool-command-routing`，基点：`05d50347f002252371a70a6f46ec8323185acef3`。本任务保持主库 v13，不改变 UI、导航、实体或 Migration；不合并 main。

## 行为与范围

十个 `time_*` 名称全部保留。四个查询工具构造 ReadTimeData；新建任务、日程、实际记录构造 CommitAssistant；周期完成构造 CompleteRecurring；显式个人规则构造 RememberRule；撤销构造 UndoCommand。time_quick_action 复用原解释器、预览、追问和确认，写入同一执行器；自然语言查询由 ReadAssistantQuery 保留周查询、空闲等原有语义。本地预览确认和聊天执行也提交 CommitAssistant，不再自行建立第二层助手事务。

生产插件读取锁定 DSH `0.2.1-rc.2` 的真实 `exec.callId`。从持久 assistant/message 的工具块关联消息，以事件 seq 生成 messageId；只有工具调用事件时使用 tool/call 的 seq。PTC 子调用通过 rootCallId 定位父消息，同时保留各自 callId。缺少稳定标识时拒绝执行。没有读取不存在的 exec.messageId / exec.toolCallId。

原生 requestId 是 sessionId、messageId、toolCallId 的 JSON 数组经 UTF-8 SHA-256 后加 `fish:` 前缀。HTTP host 仍为每次请求生成独立传输 id；重发的传输 id 可以不同，业务 requestId 不变。在同一 Room 事务内先查询持久结果再读取现状、解析、规划、写入。执行成功但回应丢失、桥对象重建、并发重发、撤销后重试均不再次写入或撤销别的操作。只缓存 APPLIED，沿用 30 天保留期。

查询保留旧顶层 plans/tasks/projects 等数据，增加 status、requestId、affected、message、conflict，实体带 version，日程带 kind。写入保留 id/message/undoAvailable，并附标准结果。需要确认时使用共享 NEEDS_CONFIRMATION；未解析或参数无效使用 INVALID，不把失败说成成功。查询不生成操作历史、命令日志或数据变更事件。

time_complete_task 必须传查询所得 expectedVersion；time_create_plan / time_record 关联 taskId 时也必须传所见任务版本。旧的双参数 Kotlin 入口保留兼容，但正式 FishSession 使用带身份的入口，不享受省略版本的兼容逻辑。ISO 时间继续要求带偏移，日程支持 TIMED / POINT / ALL_DAY；POINT 的 start=end，全天的 start/end 对应包含首尾的日期，按 timezoneId 或本地时区归一化。

新写入的任务、实际记录、日程和鱼启动的计时标注 FISH；修改已有条目保留原 source/sourceRef，避免训练详情和健康来源关联丢失。日程 sourceRef 使用已有列；v13 的 Task/TimeRecord 没有 sourceRef 列，因此会话回链保存在同事务的 command_log 结果 sourceRef，并通过 affected 实体 ID 关联，没有伪造实体字段或占用后续迁移版本。这项回链随 command_log 的 30 天保留期，不能当作实体永久 sourceRef；未新增对话回链 UI。

周期任务仍调用原 RecurringService 状态更新规则，包括实例、任务和提醒，不补写实际投入。项目归属与新任务为一个事务和一个撤销组。批量删除超过 10 条时，鱼确认文本不能绕过 App 业务页面的确认。停止模型生成不隐式撤销已提交业务。

现存日程/训练通知没有“完成/停止”按钮，只有打开页面的点击入口。本轮把现存提醒 deliveredAt / 投递哨兵认领接入稳定 DeliverReminder 命令；只有首次 APPLIED 才允许 post，重复或陈旧广播不再发送。投递状态不创建用户撤销记录，保留原防重响策略。N06 常驻计时和后续提醒按钮未提前新增。

## 实测与审查过程

- 新工具身份 Kotlin 契约先编译失败；补兼容入口后 9 项新行为测试全红，确认没有假绿。
- DS 身份辅助模块缺失时 Node 测试失败；接入候选代码后 7 项身份测试通过。
- 实际插件注册与 HTTP 测试模拟首次请求到达、响应被取消，再重发同一次工具调用，核对身份逐字段一致；同时验证十个名称和 QQ 群私人业务隔离。
- 首次定向回归 241 项、4 失败：两个旧断言仍按 TASK / COURSE_BATCH 顶层历史计数，而新执行器按规格形成 ASSISTANT_BATCH；更新为检查单一组内子操作，并保留真实撤销验证。另两个新测试夹具分别触发原有“同名需确认”和“提醒需未来时间”规则，修正夹具，没有放松业务规则。
- 扩展测试复现鱼计时 source=TIMER，修正为 FISH。固定时钟下立即停止触发原有最短计时校验，测试改用同库、推进两秒后的时钟。
- 独立规格审查指出嵌套事务回滚会覆盖 INVALID/CONFLICT。工具桥携带结构化拒绝穿出外层回滚边界，保留 rollbackOnly 保护；新增项目失败精确状态和旧预览确认冲突验证。

## 协作

WorkBuddy CLI 本轮版本 2.171.0。只向 DS 提供协议要求和合成事件，不提供手机、健康库、聊天、Key、凭据或私密日志。DS 仅输出 tool-identity.mjs 与对应测试的候选 JSON；禁止工具/MCP、实际工具调用 0，限一次生成、180 秒、CLI max-turns=2，超时终止。响应模型确认 deepseek-v4.1-flash；effort=max 为请求值，服务端实际 effort 未返回。CLI 报告的 turns 与工具调用次数分别记录，不混为一谈。

主代理独立审阅并写入候选文件，控制 index/FishSession、命令、Repository、实体、最终集成、构建与 Git。规格和质量审查使用独立 Codex 只读代理，与 DS 实际编码记录分开；审查不冒充测试。
