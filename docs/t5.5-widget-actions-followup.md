# T5.5 今日概览的最近计时操作

日期：2026-11-05。影响 L02/L03/L07，关联 N02/N03/N09。

## 实际改动

今日概览原来的“开始最近计时”只打开快捷记录管理页。本批从完整快捷记录集合中选取最近使用的 START_TIMER/START_FOCUS 项，不受固定项或四个可见芯片的截断影响；相同最近时间按使用次数、显示顺序稳定选择。

计时区现在复用快捷计时芯片已有的 StartWidgetEntry ActionCallback，携带所见 entryVersion 和稳定 requestId，经 WriteQuickEntry/Perform 启动。不在回调重新读取最新版本后静默确认，不传入已运行槽位以擅自结束当前计时；冲突仍由原命令拒绝。成功后沿用原组件刷新路径。没有可启动项时明确显示“设置快捷计时”，进入管理页而不是假装已开始。

本批没有 schema 变更，没有新增主计时引擎或每秒刷新组件。

## 本轮验证

只执行必要 `./scripts/build.ps1 -Tasks @(':app:compileDebugKotlin')` 及差异/资源检查，真实结果见 `ledger-evidence/development-20261105/widget-actions.json`。没有运行测试、lint 分析或手机操作，不能据此宣布小组件验收通过。

## 待验收步骤

1. 设置多个固定/未固定的快捷记录，使最近的计时项不在前四个芯片；点今日概览计时区，核对实际启动正确项。非计时动作不应被当作最近计时。
2. 同一可见组件快速重复点按，核对稳定 requestId 只产生一个计时或专注；停止后组件刷新，再点按可开始下一次。
3. 展示后从其他入口修改/删除快捷记录，或启动自由计时/专注/训练，再点旧组件，核对拒绝而不静默替换主计时。
4. 没有快捷记录、进程被杀、锁屏、通知权限关闭、无 Key/网络/运行时，及两种呈现模式均需设备核对。

## 尚未解决

- 现有 widgetResult 失败时只保留错误并刷新组件，用户仍需点错误进入应用；尚未达到规格“失败时打开 App 显示原因”。本批不添加从 ActionCallback 直接 startActivity 的替代：Android 官方 Glance 交互文档提示 Android 12+ 不应从服务/广播回调作为 activity trampoline，而应使用 actionStartActivity。需要后续独立实现符合平台约束的失败/确认入口，不以这条限制删减原要求。
- 官方依据：`https://developer.android.com/develop/ui/compose/glance/user-interaction`（2026-11-05读取）。主代理已核对实际源码，不直接把只读审查结论当作修改依据。
- 通知栏“最近计时”的旧 quick-recent 路由仍是管理页，本批只处理 N02 小组件，不宣称 N06 已补齐。
