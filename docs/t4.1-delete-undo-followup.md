# T4.1 任务与项目删除的命令及撤销提示

日期：2026-11-05。影响 L01/L02/L03/L05/L07；关联 N03/N07。

## 实际改动

- 任务删除新增 `DeleteTask` 命令。确认前从数据库读取任务、全部未删除关联日程及关联提醒的版本；确认框保存该预览和稳定 requestId，不随后台刷新静默更新所见版本。
- 提交时重新核对完整关联集合和版本。期间新增、删除、关联或修改日程/提醒时，拒绝整次写入并要求重新打开核对。
- 保留关联日程的两种选择：一起删除，或者解除任务关联并保留标题成为独立日程。实际记录、附件原件、任务归属和历史不在本次删除中清除。
- 已开启的关联提醒通过现有 ReminderInstanceRepository 关闭，取消待触发的派生实例。来源和重复配置保留；没有另建闹钟机制。允许关闭已过去或已完成任务的提醒，以便完成删除事务。
- 关联自由计时或专注尚未结束时拒绝删除，不因其他任务正在计时而阻止本任务删除。
- 日程、提醒/派生实例、任务写入复用 CommandExecutor 的一个事务、command_log 和历史组。历史顺序为日程、提醒/实例、任务；撤销逆序先恢复任务，再恢复提醒/实例和日程。旧 repository 调用入口也改经同一命令。
- 任务删除接入根页面已有八秒 UndoSnackbar；项目删除调用既有 WriteProject，增加同一共享组件的八秒撤销提示。项目下任务与历史归属继续保留，仍可从历史恢复。

主库仍为 v22，训练库仍为 v1，没有 schema 变更。不更改任务完成语义，不生成实际记录。

## 恢复授权后待验收

1. 新建带日程、任务提醒、重复/稍后实例及附件的任务，分别选择两种删除方式；核对实际记录、附件原件和历史归属保留。
2. 删除后八秒内点撤销，核对任务、日程关联、提醒开关、重复配置和实例恢复；再重做，核对没有重复日程或闹钟。到期后仍可在历史恢复。
3. 在确认框打开后从另一入口新增/修改/删除关联日程或提醒；旧确认必须拒绝，不能部分删除。
4. 同 requestId 重放只删除一次；确认框旋转/状态恢复后仍使用原预览。正在关联计时/专注时拒绝删除，结束后可重试。
5. 删除项目并撤销，任务和历史归属始终保留；四种外观、200% 字体、TalkBack、无 Key/网络/运行时，以及锁屏/后台后的通知撤销均需设备核对。

## 已知限制

八秒提示是当前页面内的即时反馈，切走页面或进程结束后的恢复仍使用操作历史。本批没有扩展为跨进程保存 Snackbar。已有提醒恢复与后台重排的真实时序未验证；测试恢复后需核对，不以源码顺序代替验收。其他模块的删除反馈、周期转换、草稿和阶段 2–5 全项对照仍需继续处理。
